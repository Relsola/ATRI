# Compiler 子项目协作约定

## 项目定位与修改范围

- ATRI 是用户的大型个人项目；Compiler 是它的基础子项目，也是当前第一步。
- 当前编译器任务的文件修改限定在 `Compiler/` 及其子目录。只有用户明确扩大范围时，才修改 ATRI 根目录或其他子项目。
- Git 仓库根目录是父目录 ATRI；复用该仓库，不在 Compiler 中创建嵌套 Git 仓库。
- 执行提交时只暂存当前任务涉及的 Compiler 路径，保留根目录及其他子项目的无关改动。
- 本轮规范讨论的后续修改先保存在本地工作区，不自动执行 Git 暂存、提交或推送。待用户明确要求提交一版，或明确确认标准定稿并要求统一提交时，再执行对应操作。

## 工作流程与文档归属

- 修改前核对相关源码和当前 diff，保留用户未提交改动。沿用现有接口和数据结构，已授权的局部修正直接完成，不顺带扩展范围或预建通用框架。
- 默认只维护当前实现；接口、语法、文件路径及格式变化时同步调用方、脚本、测试与文档。除非用户要求，不主动保留旧语法兼容、旧路径回退、占位接口或静默降级。
- 重要语言/IR/自举路线调整应说明性能、内存、复杂度及维护影响，按用户已有决定和本次授权推进；设计决定写入对应文档。
- 代码风格、工具经验和验证选择见[开发约定](docs/development.md)，按任务读取相关章节；不复制其他项目的 skill 路径或假定其工具已经接入。

## 语言设计与文档

- `NEXT/language_spec_v0_1.md` 是语言规则的统一维护入口；架构与自举路线见 `NEXT/self_hosting_compiler_design_v0_1.md`。
- 声明采用 `name: Type`（参数、绑定与命名字段）；函数沿用 `fn name(...) -> Type`，顶层函数不需要前向声明。当前实现范围见 `NEXT/parser_subset_v0_1.md`，IR 内部契约见 `NEXT/ir_design_v0_1.md`。
- 普通变量去掉 let：`name: Type [= expression];`，可变并保留默认初始化；结构体优先使用字段声明的默认值，其余字段按类型默认初始化。编译期常量统一为 `name: Type := expression;`，求值失败必须报错，不再提供运行期 const 绑定。`::` 用于模块限定访问及 `name :: import` 模块绑定，类型推导简写待定，不与常量声明复用。
- 模块导入形式、单次加载、重名诊断及定义模块名称解析已确认，统一见语言规范第 11 节；已实现相对 .ar 导入、函数/标量全局导出及共享全局存储，不含隐式原子操作或同步。当前初始化与路径边界见实现子集，不代表完整模块/全局系统已完成。
- 当前指针支持 `*i32`、C 兼容 `*char` 和结构体指针 `*T`，不增加独立引用类型。i32/结构体可取地址与显式解引用读写；同类指针支持 null、参数/返回及 ==/!=，正大小目标支持元素偏移和 i64 差值。结构体指针须 `(*p).field` 显式解引用；零大小目标算术报错。其他边界见指针子集及实现子集。
- 结构体已实现名义类型、自然布局、字段默认值/指定初始化、嵌套读写、按值复制/传参/返回及 Windows x64 C ABI 验证。字段默认值当前限可编译期求值的标量，结构体全局和 := 聚合常量仍未实现；实现边界统一见语言子集，不以功能通过承诺复制已消除或性能已达标。
- 已确认字符指针与 C 一致、内置 string 整体暂缓、稳定 ABI 目标与目标 C 一致。已实现 `[[extern(C)]]` 固定签名声明和 puts 最小调用；字面量与 ABI 规则统一见语言规范第 5.5/13 节。完整 C ABI、正式导出、回调及可变参数尚未实现，不以最小调用通过替代完整验收。
- 当前整数原型经用户允许暂用 BD-06 候选行为，仍须保留待审查状态；浮点运算本轮暂缓，不据此移除长期类型目标。
- 为完整表达 64 位指针偏移/差值，已实现 i64 值、算术、常量求值和调用；普通 i32/i64 之间仍无隐式转换，指针目标类型没有自动扩展为 *i64。指针算术的边界契约沿用 BD-14 候选，不将机器地址环绕当成合法行为。
- 语言核心定位为 DOP（面向数据编程）；优先考虑显式布局、数据组织与批处理，不据此自动增加 OOP 机制、专用 SoA/SIMD 功能或扩大自举范围。
- 用户已授权先拟定基础默认行为再审查；候选规则和理由见 `NEXT/language_defaults_review_v0_1.md`，未经用户接受不升级为已确定规则。
- 运行时零开销是用户明确要求的设计方向；应说明默认检查、隐式分配/运行时及必要语义成本，不把默认零初始化等必要操作描述为无成本。
- 区分用户已确定的规则、当前建议和待定事项；不得将讨论建议自动写成冻结规则。
- 完善规则时同步示例、关联决策编号和验证预期。进入实现的功能应具备足够明确的语法与语义。
- 第一次自举与完整 Comptime/AST 元编程的先后依赖尚待确认，沿用已记录路线，不能擅自缩减目标。

- BD-19 已接受并实现：bool 条件、强制块、if/else、while/do/for/loop、最近循环 break/continue；IR 为多块 CFG。当前支持 bool 值/比较/短路及编译期循环/递归；多块函数暂保守保留存储与跳转，不套用单块优化。defer 尚未实现；详见子集与 IR 文档。

- 数组声明/初始化采用 `data: [N]u8 = {1, 2};`，已接通固定数组、u8/*u8、多维/字段索引、按值复制/传参/返回；长度求值、缺省元素和 ABI 等原型边界见实现子集，不自动冻结 BD-12/15。尚无数组全局、聚合编译期值或动态数组。
- 用户已澄清 run 为编译期执行。本轮支持 `run name: Type := expression;` 与标量 run 表达式，强制求值独立于优化；完整 run 代码块及 AST 元编程继续待实现，自举路线不因本轮标量实现自动变更。

## 验证与交付

- 按改动选择现有验证入口，先构建再运行相应测试；纯文档核对相关源码、链接和差异即可。遵守用户明确的暂停构建或延后回归要求。
- 失败先保留退出码和原始诊断，定位首次失败；不以反复重跑替代根因说明。仅在有新改动或未解决问题时扩大验证。
- 交付说明改动、实际执行的检查、未验证项和已知限制；区分解析成功、IR 检查、原生执行、代码生成效果与实际性能，不将一种证据当成另一种保证。
