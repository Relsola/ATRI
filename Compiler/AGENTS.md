# Compiler 子项目协作约定

## 项目定位与修改范围

- ATRI 是用户的大型个人项目；Compiler 是它的基础子项目，也是当前第一步。
- 当前编译器任务的文件修改限定在 `Compiler/` 及其子目录。只有用户明确扩大范围时，才修改 ATRI 根目录或其他子项目。
- Git 仓库根目录是父目录 ATRI；复用该仓库，不在 Compiler 中创建嵌套 Git 仓库。
- 执行提交时只暂存当前任务涉及的 Compiler 路径，保留根目录及其他子项目的无关改动。
- 本轮规范讨论的后续修改先保存在本地工作区，不自动执行 Git 暂存、提交或推送。待用户明确要求提交一版，或明确确认标准定稿并要求统一提交时，再执行对应操作。

## 工作流程与文档归属

- 修改前核对相关源码和当前 diff，保留用户未提交改动。沿用现有接口和数据结构，已授权的局部修正直接完成，不顺带扩展范围或预建通用框架。
- 默认只维护当前实现；接口、语法、文件路径及格式变化时同步调用方、脚本、测试与文档。除非用户要求，不主动保留旧语法兼容、旧路径回退、占位接口或静默降级。
- 重要语言/IR/自举路线调整应说明性能、内存、复杂度及维护影响，按用户已有决定和本次授权推进；设计决定写入对应文档。
- 代码风格、工具经验和验证选择见[开发约定](docs/development.md)，按任务读取相关章节；不复制其他项目的 skill 路径或假定其工具已经接入。

## 语言设计与文档

- 编译器指定能力使用单个 `#`，包括 `#run`、`#insert`、插件内的 `#keyword`、`#extern(C)` 和 `#through`。`#` 与能力名可有空白。cast/sizeof/alignof 属于运算符，import/export/defer 各自保留语法。两种 `#run` 块均已接通编译期 VM。源码展开与插件能力见语言规范第 12 节。
- 枚举使用 `[export] Name :: enum [(Type)] { Member [= constant], ... }`。默认 i32、从 0 递增；bit8/16/32/64 对应同宽无符号整数，从 1 逐位左移，成员声明不允许 0 或复合位，容量溢出报错。枚举名是底层整数别名，成员是其整数常量，不引入独立枚举值类型或有效值域；可直接计算、索引，存储/运算结果允许 0。具体整数间的符号/位宽转换仍沿用现有规则，当前成员初值求值限制见实现子集。
- 用户已撤回 match，采用 switch/case/default：选择值求值一次，case 强制编译期求值并检查重值；非空分支默认不贯穿，连续空标签共享后续分支，#through; 只能位于非末尾分支结尾。case 不强制 {}、各分支作用域独立，可任意嵌套词法块。break 退出最近 switch/循环，continue 仍寻找最近循环；不添加模式/解构/穷尽系统。首版用比较链及已有多块 CFG，不承诺跳转表。

- `NEXT/language_spec_v0_1.md` 是语言规则的统一维护入口；架构与自举路线见 `NEXT/self_hosting_compiler_design_v0_1.md`。
- 声明采用 `name: Type`（参数、绑定与命名字段）；函数沿用 `fn name(...) -> Type`，顶层函数不需要前向声明。当前实现范围见 `NEXT/parser_subset_v0_1.md`，IR 内部契约见 `NEXT/ir_design_v0_1.md`。
- 普通变量去掉 let：`name: Type [= expression];`，可变并保留默认初始化；结构体优先使用字段声明的默认值，其余字段按类型默认初始化。编译期常量统一为 `name: Type := expression;`，求值失败必须报错，不再提供运行期 const 绑定。`::` 用于限定访问、`name :: import` 模块绑定及 `Name :: enum`，类型推导简写待定，不与常量声明复用。
- 模块导入形式、单次加载、重名诊断及定义模块名称解析已确认，统一见语言规范第 11 节。已实现相对 .ar 导入、函数及标量/聚合全局导出和共享全局存储。当前初始化与路径边界见实现子集。
- 数据指针支持多级 `*T`，可对可变指针对象取地址，每次显式 `*` 解引用一层。指针算术依据直接目标的大小，同类型差值返回 i64。直接目标为 void、opaque 或零大小时禁止算术，void/opaque 不可访问对象。所有层级沿用当前目标的数据指针 ABI，详细边界见指针子集。
- 结构体已实现名义类型、自然布局、字段默认值/指定初始化、嵌套读写、按值复制/传参/返回及 Windows x64 C ABI 验证。已支持结构体普通全局的默认/指定静态初始化，包含嵌套结构体与字段数组；标量叶子必须可编译期求值，指针初值限 null。字段默认值当前限编译期标量；:= 聚合常量、聚合调用/复制初始化和非零地址重定位仍未实现，准确边界见语言子集，不以功能通过承诺复制已消除或性能已达标。
- 已实现简单无标签 union，语义入口为语言规范第 9.2 节：目标 C 自然重叠布局、合法表示的跨成员读取、整块零初始化、单成员指定初始化、成员访问/取地址、按值复制/调用、普通全局静态初始化及模块导出。复用 struct 名义类型表，以 is_union 区分布局，不添加运行期标签或检查。暂不支持成员声明默认值、匿名成员、位域、空 union 定义或聚合编译期值；C ABI 仅验证当前 Windows x64 已支持类型范围。
- 已确认字符指针与 C 一致、内置 string 整体暂缓、稳定 ABI 目标与目标 C 一致。已实现 `#extern(C)` 固定签名声明和 puts 最小调用；字面量与 ABI 规则统一见语言规范第 5.5/13 节。已补齐支持类型的 C 可变参数调用、void 返回与 stdio 文件读写；完整 C ABI、正式导出、回调、浮点变参和可变参数定义端尚未实现，不以最小调用通过替代完整验收。
- BD-06 整数运算及基础位运算/移位、复合赋值已获用户接受并实现：八种定宽整数环绕，有/无符号一元负号均保留，非法除余/移位动态不检查。定型、求值顺序及优先级统一见语言规范第 5.4/7 节。浮点运算继续暂缓，不据此移除长期类型目标；本轮不增加八进制整数或 ++/--。
- 为完整表达 64 位指针偏移/差值，已实现 i64 值、算术、常量求值和调用；普通 i32/i64 之间仍无隐式转换，后续基础类型补充已接通 *i64 及其余整数/bool 一层指针。指针算术的边界契约沿用 BD-14 候选，不将机器地址环绕当成合法行为。
- 语言核心定位为 DOP（面向数据编程）；优先考虑显式布局、数据组织与批处理，不据此自动增加 OOP 机制、专用 SoA/SIMD 功能或扩大自举范围。
- 用户已授权先拟定基础默认行为再审查；候选规则和理由见 `NEXT/language_defaults_review_v0_1.md`，未经用户接受不升级为已确定规则。
- 运行时零开销是用户明确要求的设计方向；应说明默认检查、隐式分配/运行时及必要语义成本，不把默认零初始化等必要操作描述为无成本。
- 区分用户已确定的规则、当前建议和待定事项；不得将讨论建议自动写成冻结规则。
- 完善规则时同步示例、关联决策编号和验证预期。进入实现的功能应具备足够明确的语法与语义。
- 第一次自举与完整 Comptime/AST 元编程的先后依赖尚待确认，沿用已记录路线，不能擅自缩减目标。

- BD-19 已接受并实现：bool 条件、强制块、if/else、while/do/for/loop、最近循环 break/continue；IR 为多块 CFG。当前支持 bool 值/比较/短路及编译期循环/递归；多块函数暂保守保留存储与跳转，不套用单块优化。BD-20 已实现带可选 bool 条件的块和单调用形式，清理时求值，外层 return 先保存结果，规则见语言规范第 8.2 节。

- 数组声明/初始化采用 `data: [N]u8 = {1, 2};`，支持全局静态初始化、`mat[i, j]` 逐层索引、按值复制/传参/返回。长度求值、缺省元素及 ABI 边界见实现子集，BD-12/15 其余提案仍待审查。聚合编译期值和动态数组尚未实现。
- `#run` 的调用形式仅接直接函数调用，如 `#run f();` 或 `a: Type = #run f();`。独立调用支持丢弃标量结果或调用 void，使用结果时由声明决定绑定语义。任意表达式的强制求值使用 `:=` 或 `case` 的既有规则。无结果块和显式返回值块见语言规范第 12.1 节。
- #run 求值阶段与接收绑定的可变性分开；编译期观察功能不要求统一源码阶段或源码回写。当前只有已求值 IR 输出，求值记录/生成代码视图及其参数仍待实现，规则与边界统一见语言规范第 12 节。

- 整数转换已确认并实现为 `cast(Type, expression)`，不保留旧尖括号或 C 式转换；缩窄保留低位、扩宽按源类型符号/零扩展，首轮无 bool 整数/指针整数转换，C 互操作所需的数据指针 cast 已在后续增量补齐。已补齐 u64 及 sizeof/alignof 的目标布局查询，首个 Windows x86-64 结果为 u64 编译期值；后续基础类型补充已接通 *u64；BD-06 已接受，TYPE-03 的其他候选继续待审查。

- C 可变参数当前支持 extern(C) 的 `...` 声明/调用，i8/u8/i16/u16/bool 尾参按目标 C 默认提升为 i32；固定前缀仍精确类型检查。void 返回、*void、opaque `struct FILE;` 及数据指针 cast 已接通 stdio；当前不是完整 C ABI 或完整类型前向声明系统，浮点/定义端等边界见实现子集。编译期 C 调用通过 VM 宿主绑定按签名执行，未绑定函数报错，见语言规范第 12.2 节。

- 基础类型补充已实现 i8/i16/u16/u32，八种整数共用定型、转换、布局与运算规则；bool 采用 1 字节、0/1 表示。用户后续已确认取消内置 char 及兼容别名：单引号字节字面量固定为 u8，支持普通字节算术和直接索引，字符串字面量为 *u8、UTF-8 正文并额外附加终止零。常用转义含独立 \0，\xHH 固定两位；不支持八进制整数/转义，前导零仍为十进制。兼容 C 的存储/调用表示，不要求兼容其源码解析。浮点与内置 string 继续暂缓。

## 验证与交付

- 按改动选择现有验证入口，先构建再运行相应测试；纯文档核对相关源码、链接和差异即可。遵守用户明确的暂停构建或延后回归要求。
- 失败先保留退出码和原始诊断，定位首次失败；不以反复重跑替代根因说明。仅在有新改动或未解决问题时扩大验证。
- 交付说明改动、实际执行的检查、未验证项和已知限制；区分解析成功、IR 检查、原生执行、代码生成效果与实际性能，不将一种证据当成另一种保证。
