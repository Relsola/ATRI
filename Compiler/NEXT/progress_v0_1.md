## 声明插件、编译期 VM 与三档原生后端（2026-11-21）

Stage 0 在解析每条顶层声明后按 `--meta` 顺序投递。`#insert #run` 在声明成形前展开文本，普通 `#run` 在插件改写完成后执行并回填常量。O0 直接生成 x64 汇编，O1 和 O2 从同一份寄存器字节码生成 LLVM IR。诊断可沿生成文本追溯至插件或插入点。[编译链与示例](../docs/metaprograms.md) · [诊断](../docs/diagnostics.md)

## 本次增量：全局数组、逗号索引与 defer（2026-11-18）

固定数组可在模块顶层静态初始化和导出，逗号索引复用逐层索引。`defer` 已接通带可选 bool 条件的块及直接调用，见[语言规范第 8.2 节](language_spec_v0_1.md#82-defer)。清理代码生成在作用域退出边上，多条边可重复展开，未测量性能。

构建及 CTest 七组通过。Windows x64 原生回归在 `-O0` 和 `-O1` 下验证全局数组与跨模块共享、多维索引求值顺序、各类延迟清理路径和返回值行为。测试覆盖范围见[测试说明](../tests/README.md#数组与-run-回归)。

## 本次增量：收束 `#run` 与多级指针（2026-11-18）

`#run` 仅接受直接函数调用，`case` 继续独立求值常量标签。已删除旧枚举语法草稿。多级数据指针支持逐层解引用、指针对象取地址、同类型比较、按直接目标大小缩放及现有 C ABI，程序入口仍为 `main() -> i32`。

构建及 CTest 七组通过。Windows 原生回归在 `-O0` 和 `-O1` 下验证多级指针的读写、偏移及双向 C 调用。IR 检查拒绝错误的解引用层数，前端验证 `#run` 的调用限制和两种保留块形式的诊断。

## 本次增量：`#run` 调用与块语法（2026-11-18）

顶层和函数内可独立执行 `#run f();`，也可在普通初始化器中使用其结果。旧声明前缀已迁移。无结果块和显式返回值块的规则见[语言规范第 12.1 节](language_spec_v0_1.md#121-能力边界)，两者当前均诊断尚未实现。

本轮构建及 CTest 七组通过。IR 回归核对独立调用在编译期执行和清除，以及普通变量仍接收已求得的初始值。`-O0/-O1` 原生回归均直接返回 2，产物只包含 `main`。

## 本次增量：C 可变参数与 stdio（2026-11-17）

用户要求 C ABI 兼容的可变参数调用与文件读取能力。本轮实现 extern(C) ellipsis 声明/调用、u8/bool 默认提升、void 返回、*void、opaque 结构体声明与数据指针 cast；补齐 fopen/fread/fwrite/fclose/ferror/feof 绑定、分块文本输出和 printf 示例。变量/对象布局、固定前缀、尾参默认提升及新类型边界同步到解析、降低、常量解释器、Verifier、优化/内联、Dump、后端和 C 测试绑定。

构建零警告，CTest 七组全部通过，包含 -O0/-O1 下真实 C va_arg 的寄存器/栈尾参、小/大结构体及隐藏返回缓冲区、void、副作用顺序，以及 257 字节二进制文件读取/EOF/失败/写回与真实 printf stdout。首次回归发现旧裸 return 解析反例需移至语义检查，以及测试绑定入口不执行模块加载；已更新反例与独立 C 驱动声明，模块调用由 read_file/variadic CLI 用例验证。后续新增 run void 诊断预期已按实际类型检查阶段修正。未测量性能；C stdio 的 I/O、缓冲、锁和分配以及原型临时槽/复制仍有成本。

当前不含浮点变参、ATRI 可变参数定义/va_list、完整前向声明、函数指针、格式静态检查或宽路径；不能据此宣称完整 C ABI。编译期观察的讨论已更新到语言规范第 12.5 节，当前 --emit-ir-before-opt 可观察已求值 IR；未增加 -r 或源码回写视图。先前转换/u64 与本轮改动纳入上述统一提交范围。

## 本次增量：C 字符串与 puts

按用户确认，字符指针与 C 一致，内置 string 整体暂缓，稳定 ABI 目标与目标 C 一致。已实现 `[[extern(C)]]` 固定签名声明、静态零结尾字符串字面量、`*char` 值与字节偏移，以及通过 C 运行库调用 puts；这些改动与模块、结构体实现一并整理提交。

新增 [hello.ar](../examples/hello.ar)、[c_strings.ar](../tests/cases/c_strings.ar) 和 [C ABI 驱动](../tests/c_abi_harness.c)。本轮构建零警告，前端/编译器/控制流/优化/Verifier/示例检查通过，Windows 原生测试在 -O0/-O1 下核对了真实 stdout、UTF-8 字节、内嵌零截断、寄存器与栈参数、64 位值、C 指针/bool 返回和外部内存写入。该证据不包含性能测量或完整 C ABI 验收。

## 本版提交汇总

相对上次提交 `738c757`，本版整合此前积累的本地修改：

- 声明去掉 let/const，普通变量采用 `name: Type [= expression]`，唯一显式编译期常量采用 `name: Type := expression`；新增独立常量解释器，求值失败不回退运行期。

## 已实现

当前链路：源码 → Lexer/Parser/AST → 名称/类型检查 → 强制编译期常量求值 → 多块 Typed IR → 优化 → Windows x64 汇编；Clang 负责汇编/链接。

| 部分 | 当前范围 |
|---|---|
| 声明 | fn name(args) -> Type；参数/变量 name: Type；:= 编译期常量 |
| 名称 | 先收集全部函数签名，后定义可调用；块作用域、同层重复拒绝、内层遮蔽候选 |
| 局部变量 | 普通变量可变、默认零初始化；参数只读候选，常量必须编译期成功 |
| 值与表达式 | i32、i64、bool、*i32、*char；整数算术、比较、bool 逻辑与短路 |
| 指针 | 一层 *i32/*char、null、复制/参数/返回、元素偏移/差值、==/!=；& 与显式目标读写仍限 i32 |
| C 调用与文本 | [[extern(C)]] 完整固定签名、原始 C 名称、静态字面量、puts 标准输出 |
| 控制流 | if/else if/else、while、do...while、for、loop、break/continue、return；所有体强制 {} |
| 编译期求值 | 整数/bool、函数调用/递归、分支/循环、内部可变局部；错误/依赖循环/资源限制诊断 |
| IR | 多基本块、显式跳转、条件分支、比较、局部对象/load/store/address、调用与 Verifier |
| 优化 | 直线函数传播/折叠/DCE/叶函数内联；常量 bool 分支不可达块删除 |
| 后端 | Windows x64 参数/返回/调用、栈帧、跳转、比较、展开描述 |
| 工具 | C23/CMake/Ninja；atri-parse 与 atri-cc，AST/IR/汇编输出 |

[main.ar](../examples/main.ar)、[constants.ar](../examples/constants.ar)、[pointers.ar](../examples/pointers.ar)、[pointer_arithmetic.ar](../examples/pointer_arithmetic.ar)、[control_flow.ar](../examples/control_flow.ar) 均可生成本机可执行程序，退出码为 3。常量示例在 -O0 下也直接返回 3；控制流示例同时包含循环、短路和强制求值的递归阶乘。

实现范围、限制和命令见[基础编译原型](parser_subset_v0_1.md)、[整数指针子集](pointer_subset_v0_1.md)及 [IR 设计](ir_design_v0_1.md)。

## 设计状态

已接受 BD-19，当前已实现其条件、循环与退出行为。bool 条件没有指针例外；p != null 才是显式非空检查，不保证地址有效。所有控制体和 defer 体必须用 {}；defer 的词法退出、逆序、执行时读取当前值已接受，语言无异常，defer 本身尚未实现。

保留 DOP、零隐藏运行时/分配方向、变量默认零初始化、:= 强制常量、结构体指定字段及重复字段报错、(*p).field 显式解引用、顶层函数无需前向声明。数组已选择 C 布局及有限静态检查；BD-16 自然布局接受，空结构体大小 0、对齐 1。聚合相关规则尚未进入实现。

整数规则暂用 BD-06 候选；求值顺序/短路、bool 布局、参数只读/遮蔽和 for 头部详细范围按当前候选落地，均未自动冻结其他提案。正式状态以[规范](language_spec_v0_1.md)和[审查稿](language_defaults_review_v0_1.md)为准。
