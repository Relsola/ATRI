# Stage 0 进度记录 v0.1

> 更新：2026-11-16。此次整理保存当前可运行原型和规范讨论进度，不表示语言规范已经定稿。

## 已实现

当前执行链路为：源码 → Lexer/Parser/AST → 名称与类型检查 → i32 IR → 优化 → Windows x64 汇编。Clang 负责将生成的汇编转换为目标文件并链接。

| 部分 | 当前范围 |
|---|---|
| 声明 | `fn name(args) -> Type`；参数与局部绑定使用 `name: Type` |
| 名称解析 | 先收集所有函数签名，允许调用后定义的函数；检查重复与未知名称 |
| 局部绑定 | const 显式初始化且不可重新赋值；let 默认零初始化并允许赋值 |
| 整数 | 可执行类型为 i32；十进制字面量、括号、`+ - * / %` 和一元正负号 |
| 调用 | 直接函数调用、参数与返回值检查；递归调用保留 |
| IR | 单 entry 基本块、有类型的值与调用、源码区间、文本输出、Verifier |
| 优化 | 已知值传播、常量折叠、死指令消除、小型非递归叶函数内联 |
| 后端 | Windows x64 整数调用、栈帧、栈展开描述和汇编文本输出 |
| 工具 | CMake/Ninja；atri-parse 输出 AST，atri-cc 输出 IR 或汇编 |

验收示例为 [main.txt](../examples/main.txt)：main 通过两个 const 绑定取得 1 和 2，调用后面定义的 add。默认优化后 main 的执行指令直接为 `mov eax, 3; ret`，原生程序退出码为 3。单独的 add 定义仍保留，尚无跨函数删除未引用定义的优化。

实现边界、命令和错误行为见[整数编译原型](parser_subset_v0_1.md)，内部表示与优化策略见 [IR 设计](ir_design_v0_1.md)。

## 规范讨论状态

已确认的语言方向与行为包括：DOP、运行时零开销方向、显式转换与 bool 条件、默认零初始化、const 必须初始化、结构体指定字段初始化、重复字段初始化报错、指针显式解引用后以点号访问字段，以及顶层函数无需前向声明。

控制体和 defer 体必须使用 `{}`；defer 在词法作用域退出时逆序执行，读取执行时的变量当前值；语言没有异常。数组采用 C 兼容布局，当前只要求有限静态越界检查。BD-16 自然布局已接受，空结构体大小为 0、对齐为 1。上述已确定规则中尚有多项未进入实现。

本轮统一声明拼写为 `name: Type`。i32 原型经用户允许暂用 BD-06 的环绕/除余候选规则，但该候选仍待审查；参数只读、局部作用域和求值顺序等原型采用的候选边界也没有自动升级为最终标准。完整状态以[语言规范](language_spec_v0_1.md)和[默认行为审查稿](language_defaults_review_v0_1.md)为准。

## 验证记录

在 Windows x86-64、Clang 23.1.2、C23 与 Ninja 下构建，启用警告作为错误。CTest 四组全部通过：

1. 前端：AST、优先级、嵌套实参、源码定位、BOM/换行、非法输入、扩容和深度限制。
2. 编译器：整数边界、名称/类型、绑定可变性、函数调用、折叠/内联和 IR 不变量。
3. 示例：命令行解析当前 main.txt。
4. 原生：在 -O0/-O1 下分别汇编、链接并运行；验证示例退出码 3，以及 C 调用动态整数函数时的负数除余、环绕、局部绑定、嵌套调用和六参数传递。

这些验证不代表审查稿中的全部语言行为用例已实现。

## 尚未完成与后续顺序

- 当前可执行类型仅 i32；浮点运算按用户要求暂缓。
- 尚无条件/循环、多基本块 CFG、指针/聚合、模块、外部函数调用、run 和 AST 修改 API。
- 非恒定临时值仍采用栈槽，没有通用寄存器分配；后端限制栈帧小于 4096 字节、每次调用至多 256 个实参。长期零开销目标仍需逐步验收。
- 当前只完成 M0 的整数纵向链路，M0 对控制流、结构体和基本 C 调用的完整验收尚未达成。

建议后续先审查整数/转换和作用域边界，再加入 bool、比较与条件分支，扩展 IR 的基本块和跳转；随后推进循环、结构体/指针及外部调用。完整自举与编译期 AST 元编程的既有路线继续保留，不因本轮原型而缩减。
