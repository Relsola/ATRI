## 1. 审查方式与约束

用户授权先形成一套基础默认行为，再审查与修改。本文的 BD-00 至 BD-29 是一套相互配合的提案，每项包括行为、理由及主要影响；不表示用户已经接受所有选择。

**已审查决定（2026-11-16）：**语言以 DOP（面向数据编程）为核心定位；BD-16 接受，唯一修改为将空结构体大小从 1 改为 0 字节，对齐保持 1。新增零大小对象的配套设计不随本条自动接受。

**已审查决定（2026-11-16）：**用户拒绝指针在布尔上下文中的特殊转换。BD-02、BD-09 中“条件与逻辑操作数严格为 bool、指针判断保持显式”的部分已接受并合入主规范；这两个条目的其他内容仍是提案。BD-19 已在后续审查中全部接受，见下。

**已审查决定（2026-11-16）：**BD-19 的条件、循环和退出规则全部接受。BD-20 在后续审查中确认词法作用域、逆序与实际执行时读取变量，其余清理细节仍单独审查。

**已审查决定（2026-11-16）：**语言没有异常；defer 不在登记时取得变量/参数快照。硬件故障、客户机异常和编译诊断不因此消失，它们与语言异常机制分别定义。

**已审查决定（2026-11-16）：**结构体指针必须显式解引用后使用点号访问字段，如 `(*p).value`；点号自身不解引用指针，也不提供箭头成员访问。BD-13 的该部分已接受，其余指针形式提案保持原审查状态。

**已审查决定（2026-11-16）：**数组当前采用 C 兼容布局和有限静态检查，运行时检查后续再看；同一结构体初始化器重复指定同一字段为编译错误。仅这些条款升级为已接受，其他相关提案保持待审查。

**已审查决定：**分支与循环使用显式块，换行不决定代码体归属。`defer` 的块与单调用形式见 BD-20。

用户已确定的约束继续生效：默认零初始化；结构体支持 `{.field = expression}`，省略字段优先采用声明默认值，其余字段按类型默认初始化；编译期常量必须显式初始化并求值成功；模块限定访问采用 `::`；字节字符使用 u8/i8，字符串字面量使用 *u8 并补终止零；默认运行时遵循零开销原则。

**本轮范围修订：**撤回内置非拥有视图类型的语法、布局、可变性和访问提案。数组当前已确认采用 C 兼容布局和有限静态检查，不生成运行时越界检查；强类型数组的其他接口和值语义继续逐项审查。

其他已有语言目标继续保留，包括完整目标 C ABI 兼容、编译期执行、任意 AST 修改和原自举路线。本文提出的阶段划分不自动取消或后移这些目标。

审查时可直接回复编号和修改，例如“BD-06 改为只有无符号整数环绕”“BD-17 的 Payload 布局另行审查”。接受后再将对应规则合入主规范的已确定部分。

**已审查决定（2026-11-17）：**基础整数、布局、位运算/移位、复合赋值及求值顺序/优先级已接受；保留 ?:，继续暂缓浮点。用户后续确认取消独立 char，字节字符为 u8，字符串字面量为 *u8 并附加终止零；固定两位 \xHH，不解析八进制。此决定取代此前 char 算术暂缓及独立类型方案，统一见主规范第 5/7 节，其余候选仍待审查。

| 编号 | 本版默认 | 主要替代方案 | 改选后的影响 |

| BD-07 | 整数 `cast` 明确允许截断/模转换 | 默认检查能否保值 | 检查更容易发现窄化错误，但需要额外比较与失败处理 |

| BD-14/15/25 | 数组已确认 C 布局、有限静态检查，暂不动态检查；裸指针契约继续审查 | 后续加入动态检查或显式受检接口 | 当前无额外索引检查分支，但静态通过不能保证动态安全 |

## 3. 基础默认行为

### BD-00：零开销原则与适用边界

**默认行为：**未使用的语言能力不引入运行时代码、分配、类型描述符或依赖。已使用能力相对于等价的手写指针、长度、标签、调用和清理代码，不增加强制机制成本。

- 默认无 GC、引用计数、隐藏堆分配、隐式装箱、动态类型检查或通用反射运行时。
- 默认无溢出、裸指针空值和对齐检查；可静态发现的问题在编译时处理。内置数组当前只做有限静态检查，不生成动态索引检查，见 BD-15。
- 原始指针等低层操作的检查由用户代码显式表达，或由可选诊断构建模式启用；内置数组当前只做有限静态检查，运行时检查后续再讨论。诊断模式不属于默认零开销配置。
- 编译期常量声明、类型检查、名称解析、模块导入、AST API 和 `#run` 本身不残留运行时调度器。
- 默认零初始化、按值复制、枚举的标签和 `defer` 清理是对应语义所需的数据与操作，不能承诺这些操作都能消失。
- 在不改变可观察行为时允许消除零写入、复制和无用标签；不允许为满足口号而删除程序可观察的工作。
- 零开销是设计与优化目标，不保证 Stage 0 第一版或 `-O0` 总能输出与手工汇编完全一致的指令。

**理由：**使语言能够承担编译器、虚拟机、Bootloader 等底层工作，同时保留明确且可验证的语义。

**重要影响：**默认零初始化有时需要真实写内存，严格浮点和明确求值顺序也可能限制优化。这些是所选语义的成本，需要审查，不能把它们描述为免费。

### BD-01：源码、标识符与基础词法

**默认行为：**源码为 UTF-8，文件开头允许 UTF-8 BOM；支持 LF/CRLF。首版标识符采用 `[A-Za-z_][A-Za-z0-9_]*`，区分大小写，禁止遮蔽内置类型与关键字。提供 `//` 和可嵌套 `/* ... */` 注释。

整数支持十进制、`0x`、`0b`、`0o` 和数字间 `_`；不支持连续或首尾 `_`。浮点支持带数字的小数与十进制指数。采用最长合法 Token。首版不提供类型后缀。

**理由：**源码与字符串统一编码；ASCII 标识符降低首轮 Lexer 和名称规范化的复杂度。嵌套注释便于暂时注释代码块，无运行时成本。

**影响：**非 ASCII 文本可出现在注释和字符串中，不能用于首版名称；未来扩展 Unicode 标识符需要明确规范化和同形字符规则。

### BD-02：类型、布尔值与大小类型

**基础类型部分已接受并实现（2026-11-17）：**八种定宽整数、bool/void 的对象边界及首个 Windows x64 自然布局统一见[主规范第 5.1 节](language_spec_v0_1.md#51-内置类型)。字节字符使用 u8/i8，不另设 char；浮点继续暂缓，未因此接受 BD-08 的全部候选。

首版继续暂缓 isize/usize；sizeof/alignof 返回 u64 已接受。其他平台以及长度/容量/分配公共 API 的 TYPE-03 余项仍需审查，不永久固定所有平台大小类型。

### BD-03：字面量定型与普通类型转换

**整数部分已接受并实现（2026-11-17）：**上下文定型、无上下文默认 i32、普通整数无隐式转换，以及十进制/二进制/十六进制与 `_` 分隔符统一见[主规范第 5.4 节](language_spec_v0_1.md#54-类型转换与字面量)。cast 源表达式仍按普通规则定型，目标不反向改变其范围；大数可先绑定 i64/u64 再转换。

**取舍：**暂不加入八进制整数和类型后缀，前导零保持十进制。字符/字符串同样不解析八进制转义，只保留独立 \0；见第 5.5 节。浮点定型和完整类型推导仍待审查。

### BD-04：字节字符（取代独立 char 方案，已接受）

**最终确认并实现（2026-11-17）：**用户接受直接使用 u8/i8 表达 8 位数据，不提供内置 char 或兼容别名。单引号字节字面量固定为 u8，字符差值和索引按普通 u8 规则；字符串字面量为 *u8 并补终止零。转义只保留常用形式、独立 \0 和固定两位 \xHH，不解析八进制。规则统一见[主规范第 5.5 节](language_spec_v0_1.md#55-字符与字符串)。

**取舍：**撤回此前“独立 char 禁止混算、char 算术结果暂缓”的方案；'a'-0 合法，负差值按 u8 环绕，需要更宽/有符号运算时显式 cast。C 兼容限定为目标表示和调用边界，C plain char 标量按目标配置映射为 i8/u8，不继承 C 的全部字面量解析或整数提升。

### BD-05：字符指针、字符串与库容器

**已确认（2026-11-16）：**字符指针与 C 一致，内置 `string` 类型整体暂缓，待用户继续考虑；最小字面量实现契约统一见[语言规范第 5.5 节](language_spec_v0_1.md#55-字符与字符串)。此前 *const char 的拼写已随运行期 const 方案撤回，是否另设目标只读指针类型继续审查。

零结尾、内嵌零、长度单位、字面量共享与访问权限均按主规范第 5.5 节维护，此处不另定义一套字符串规则。

借用文本视图仍可由以下普通结构体示意，动态 String 可由库管理分配和释放；两者均为后续库设计候选，不据此立即增加内置类型或冻结目标可写权限：

```text
struct StringView {
    data: *u8;
    len: u64;
}
```

**理由：**无隐藏分配、引用计数或析构；底层字符串、视图和拥有内存的容器保持可区分。

**影响：**字符串拼接、Unicode 遍历和拥有型容器复制需要显式 API。库容器若持有独占内存，不能随意浅复制后分别释放；首版由使用约定处理，语言不自动添加所有权系统。

### BD-06：整数运算与边界

**已接受并实现（2026-11-17）：**定宽环绕、除余非法边界、位运算、移位数量/补位及复合赋值统一见[主规范第 7.2 节](language_spec_v0_1.md#72-数值运算与比较)。此状态取代此前“仅原型暂用”；浮点不随本项接受。字节字符按 u8 规则计算。

**本轮修正：**保留当前实现的无符号一元负号，按位宽环绕，撤回旧稿禁用无符号负号的候选。

**理由与影响：**定宽结果稳定，适合位级计算，普通运算不插入隐式检查；Stage 0 使用无符号位模式避免宿主 C 有符号溢出。代价是不能采用依赖“有符号永不溢出”的优化；非法除余/移位动态不检查，受检运算须由调用方显式表达。

### BD-07：显式 cast（整数部分已接受）

**已接受并实现（2026-11-17）：**使用 `cast(Type, expression)`。整数按数学值模目标位宽解释，缩小时保留低位，扩宽按源有/无符号性符号/零扩展；首轮不开放 bool 与整数相互转换。统一规则与语法理由见[语言规范第 7.3 节](language_spec_v0_1.md#73-显式转换)。当前支持八种定宽整数的显式转换，默认无保值检查；本轮为 C 互操作扩展的数据指针 cast 统一见主规范第 13.3 节，不开放指针整数或 bool 整数转换。未来转换模式仍需另定，不预建语法参数。

**字节字符使用普通整数转换：**u8/i8 之间按已接受的整数 cast 转换，不再提供独立 char。浮点、枚举、指针及只读权限规则如下，尚未因整数规则接受而确定。
- 整数转浮点、浮点缩窄按 BD-08 舍入；浮点缩窄溢出可成为无穷，不自动检查。
- 浮点转整数向零截断；NaN、无穷或截断后超范围为非法转换，默认不插入运行时检查。
- 枚举与整数的转换见 BD-17，指针与整数/指针转换见 BD-14。
- 不允许 cast 将只读访问权限改为可写权限。

**理由：**显式窄化具有可预测的位级语义，与原来的 `cast(u8, rgba)` 用途一致，避免隐藏范围检查。

**重要影响：**显式不等于保值。`300 -> u8` 得到 44，`-1 -> u64` 得到最大 u64；保值转换需要调用方主动检查。若希望所有 cast 都保值，应增加专门的截断操作并重新审查零开销要求。

### BD-08：浮点模型

**默认行为：**`f32/f64` 分别采用二进制 32/64 位 IEEE 754 格式；基础 `+ - * /` 和转换采用最近值、偶数舍入，保留有符号零、无穷、NaN 和非正规数。比较遵循相应浮点语义。除零可产生无穷或 NaN，不当作整数除零处理。

每个有类型操作按其精度得到结果；默认不重结合表达式、不自动融合为 FMA、不启用 fast-math。NaN 的具体载荷位和符号不保证跨实现相同；不提供普通浮点 `%`。

运行环境和外部函数须维持符合约定的浮点控制状态；不在每次调用边界自动保存/恢复环境。首个 Hosted 启动方案须验证环境符合要求，不能只依赖继承自任意宿主的状态。显式修改浮点控制状态的 FFI 调用者负责恢复。

**理由：**便于编译期与目标执行对照；采用目标原生基础运算，避免默认额外检查和环境管理。

**影响：**严格顺序限制部分数值优化；可将 fast-math 作为未来显式选择，但不能让普通 `-O` 默默改变结果。编译期浮点格式转换的正确舍入和目标环境初始化是实现前必须完成的技术契约。

### BD-09：求值顺序、短路与优先级

**基础表达式部分已接受并实现（2026-11-17）：**左到右求值、bool 逻辑短路、赋值/复合赋值语句、左侧位置只计算一次，以及包含位运算/移位/`?:` 的优先级统一见[主规范第 7.1 节](language_spec_v0_1.md#71-求值与副作用)。保留现有三元表达式，撤回旧稿“不提供 `?:`”的过时候选。本轮未加入 `++/--`；用户询问其取舍，尚未授权增加。

**理由与影响：**副作用顺序可解释、可验证；只有不改变可观察行为时才能重排。复合赋值的旧值在求右侧前取得；`flags & mask == 0` 应显式写成 `(flags & mask) == 0`。聚合初始化的其余长期细节仍随对应条目审查。

### BD-10：默认零初始化与结构体初始化

**沿用已确定规则：**普通变量无初始化器时零初始化；编译期常量必须显式初始化并求值成功；结构体使用 `{.x = value}`，缺省字段默认值规则已于 2026-11-17 补充，统一见主规范第 9.1 节。

**补充默认：**整数/char 为 0，浮点为正零，bool 为 false，指针/函数指针为 null；数组和结构体递归零初始化。枚举和 union 见 BD-17/18。

**已接受的补充：**同一结构体初始化器重复指定同一字段为编译错误，即使两次提供相同值也不允许。

其他默认提案：允许 `{}`、乱序指定字段和嵌套指定初始化，不存在字段报错。结构体首版不提供位置初始化与用户构造函数。初始化器使用目标类型，在缺少目标类型时不能作为独立的匿名值。

零初始化不保证结构体填充字节为 0，也不自动清零原始分配器返回的内存。显式分配接口负责说明其结果是原始字节还是已初始化对象。

**理由：**保留用户希望的简洁、确定行为，并把字段值和物理内存表示区分开。

**重要影响：**零值若在写入前可被观察，就有真实初始化成本。本版不新增跳过初始化的语法；未来若需要，应作为显式低层能力单独审查。

### BD-11：编译期常量与运行期变量（规则已调整）

**已确定（2026-11-16）：**去掉 let 和 const 声明关键字。普通变量使用 name: Type [= expression]，可变且保留默认零初始化；唯一的显式编译期常量声明使用 name: Type := expression，必须显式初始化并在编译期成功求值。

这取代此前“允许运行期初始化的 const 对象”及其配套目标只读限定候选。不由编译器追踪所有别名以保证指针目标永远不变；也不因常量包含指针就自动给目标增加深度只读约束。是否需要单独的只读指针 API 及其拼写，继续单独审查。

当前 i32 原型在语义阶段执行常量初始化，支持整数计算、前向函数调用及被调用函数内部的可变局部变量。常量初始化直接引用普通局部变量或运行期参数时拒绝，不让优化器是否折叠决定程序合法性。编译期错误、依赖循环或超出资源限制必须诊断，不回退为运行期计算。

**理由：**保留明确的编译期常量承诺，不引入运行期不可变绑定及复杂的别名不变性系统。

常量的聚合、实体化、取地址与地址常量规则待定。已知地址也不等于其目标内容是常量。

### BD-12：值复制、参数与返回

**默认行为：**标量、结构体、数组、union、枚举采用按值赋值、参数和返回；复制包含嵌入字段/元素的值。指针只复制地址，不复制目标数据，不隐式分配或释放。

参数绑定默认不可重新赋值，按传入值初始化；其指针目标是否可写由类型决定。要修改参数的本地值，可显式复制到普通可变变量。

重叠的聚合赋值按“先取得完整右值，再更新目标”的效果处理，不能错误使用不支持重叠的拷贝。实现可消除临时对象，但必须保留该行为。没有自动析构、用户复制构造或隐式深复制。

**理由：**值与别名关系明确，避免把普通赋值变成隐式堆操作。

**影响：**大数组按值传递可能昂贵；需要借用时显式使用指针。拥有堆内存的库类型需手动 clone/free，并避免复制后双重释放。

### BD-13：指针与函数指针的形式

**默认行为：**使用前缀 `*T`、`[N]T`；目标只读限定尚不指定语法。`null` 是按上下文定型的空指针字面量，不是整数；普通整数 0 不隐式成为指针。

函数指针候选形式为 `*fn(i32, *u8) -> i32`；`&function_name` 取得相应指针，调用使用 `callback(args)`。函数指针只存储目标地址，不携带闭包环境，不支持空指针调用。

数据指针可以显式转换为不同数据指针类型，访问权限和目标只读问题另行审查；函数指针转换仅允许相同签名与调用约定。数据指针和函数指针之间首版不允许互转。

**理由：**保持类型表达式组合一致，不引入运行期闭包分配；函数签名和调用约定可静态验证。

**影响：**当前字符指针沿用 `*u8`；若以后改成后缀形式，必须同步整个类型语法。函数指针语法仍需在完整 EBNF 中验证无歧义。

#### 结构体字段定位与显式解引用（已接受）

用户明确决定：`.` 只负责在结构体对象上定位字段；指针必须先显式 `*` 解引用，不提供成员访问运算符 `->`，也不允许点号自动接受一层或多层指针。

```text
struct Node {
    value: i32;
    next: *Node;
}

node: Node;
p: *Node = &node;
pp: **Node = &p;
node.value = 1;
(*p).value = 2;         // 写入同一个对象的字段
(**pp).value = 3;       // 两层指针均显式解引用
q: *Node = (*p).next; // 得到指针字段本身，此例为 null

p.value = 4;           // 编译错误：点号接收者是指针
pp.value = 4;          // 编译错误：不自动追踪多层指针
p->value = 4;          // 编译错误：不提供箭头成员访问
```

- `node.value` 和 `(*p).value` 使用完全相同的字段定位规则；结构体对象来自变量还是显式解引用，不改变点号的作用。
- 显式解引用得到目标对象的访问表达式，不要求读取或复制完整结构体；只有需要字段值时才读取对应字段，取字段地址时可直接形成地址。
- 指针字段保持其声明类型。`(*p).next` 为 `*Node`；继续访问目标字段时，必须先显式解引用这个指针。
- 不引入赋值、传参、返回或条件位置的通用隐式解引用。`copy: Node = p;` 是类型错误；`copy: Node = *p;` 则按按值复制提案处理。
- 指针有效性与生命周期要求继续适用；不因使用括号和点号而自动添加动态检查。
- 结构体临时值能否取地址、可写性和完整生命周期规则仍按后续提案审查；本次只确认字段定位和显式解引用边界。

**理由：**解引用与字段定位分别由 `*` 和 `.` 表达，省去另一套箭头成员语法，也避免为了访问字段引入指针特殊转换。此前“点号直接接受一层指针”的提案源于助手误解，现已撤回。

**影响：**指针链需要显式括号和解引用，代码更长，但每次经过指针都在源码中可见；生成代码不需要因此复制整个结构体，零开销方向保持不变。函数返回类型中的 `->` 保持原语法，不受成员访问决定影响。

### BD-14：地址、生命周期与原始内存

**本轮 C 互操作补充（2026-11-17）：**支持 *void、opaque 对象指针及显式数据指针 cast，规则见主规范第 13.3 节；整数地址转换、函数指针和完整生命周期/别名规则仍待审查。

**原型实现状态（2026-11-16）：**为当前 *i32 加入 p+n、n+p、p-n 和 p-q；偏移为 i32/i64，按 4 字节元素缩放，差值为 i64 元素数。暂沿用下述同存储/尾后/范围候选，不插入动态检查；完整原始指针契约继续待审查。控制流实现已加入 *i32 的 ==/!= 及 null 比较，整数/指针转换、指针排序和多层指针仍未实现。

**默认行为：**局部对象存活到词法作用域退出，全局对象存活到进程结束，动态内存由显式分配/释放管理。没有借用检查、自动释放或运行期存活追踪。

解引用必须满足非空、有效存储、足够大小、对齐、已初始化且访问权限正确；默认不插入检查。使用悬垂地址、释放后访问、越界访问或读取非法表示均为未定义行为。编译器能证明的直接返回局部地址等错误给出静态诊断，但不承诺发现所有逃逸路径。

`p + n` 和 `p - n` 按 `sizeof(T)` 缩放，仅允许在同一存储对象内或形成其尾后地址；尾后地址不得解引用。空指针和大小为 0 的目标不允许指针算术。指针差值返回 i64，要求同一对象、可被元素大小整除且结果可表示。指针相等比较允许，普通顺序比较不提供。

首个目标的数据指针与 u64 可显式互转；同一有效地址的往返保留可访问性，其他生成的整数地址仅在确实对应有效对象并满足访问条件时可解引用。地址加减、乘法或差值计算越出目标地址/差值表示范围，均为非法指针操作，不使用 BD-06 的普通整数环绕规则补救。

首版不采用基于互斥类型的严格别名优化；显式转换后的访问可以重解释存储，但须满足大小、对齐、权限和结果表示条件。通过 u8/char 指针可访问对象表示；填充字节值不保证确定，不能据此比较结构体内容。

**理由：**不在每个指针中增加区域、边界和存活元数据，为底层程序保留地址操作。

**重要影响：**这是一门默认不保证内存安全的语言。若以后希望全面检查，要引入额外机制或受检指针类型；不能只在后端补一个开关就得到完整安全性。

### BD-15：数组布局与有限静态检查（部分已接受）

**已确认语法（2026-11-17）：**数组声明及元素列表初始化采用 `data: [N]u8 = {1, 2};`；规则统一见[语言规范第 7.4 节](language_spec_v0_1.md#74-地址解引用与索引)。本次不自动接受下述完整类型/值语义或接口提案，初始化数量、长度表达式等边界继续待审查，当前 Stage 0 已实现固定数组与 u8/*u8，准确能力和候选边界见[实现子集](parser_subset_v0_1.md#固定数组的当前实现)。

**已确定：**当前采用与目标 C 数组兼容的连续元素布局，由编译器进行有限静态越界检查；暂不生成运行时索引检查。运行时检查、失败钩子和受检访问接口留待后续探索，不是当前实现要求。

**布局边界：**对元素表示与目标 C 类型兼容的正长度固定数组，元素连续存储，大小为 N 乘以元素大小，对齐与元素对齐一致，无隐藏长度/容量头部。零长度数组的大小/对齐已随 BD-16 接受，不默认承诺 C 兼容；运行期长度和动态扩容继续待定。C 布局兼容不自动采用 C 的数组退化或函数参数规则。

**静态检查范围：**常量索引、常量长度和有限的简单常量传播可以证明越界时，报编译错误；不要求证明每个动态索引安全，也不以复杂范围分析作为首版编译的前提。无法静态确定的动态索引允许编译，不自动补入检查。编译期实际执行的越界继续按编译期诊断规则处理。

```text
data: [16]u8;
data[16];              // 编译错误：可直接确定越界
i: u64 = read_index();
data[i];               // 允许编译；当前无自动动态边界检查
```

**重要边界：**静态检查通过不保证运行期索引合法。程序员仍须保证 `0 <= index < N`，需要保护动态输入时显式验证；不能依赖编译器自动报告、终止或返回错误。本次决定的是布局与检查范围，非法运行期访问是否归为未定义行为等分类仍由内存契约另行确定，不因缺少检查而变为合法访问。

**其他数组候选继续待审查：**`[N]T` 中元素类型和长度共同构成类型，整体赋值/参数按值处理，不自动退化为指针；`.len` 作为编译期长度，`.data` 显式取得元素指针。这些类型与接口规则不因确认 C 布局而全部自动接受。

**理由：**当前不引入索引检查分支或故障处理依赖，保持底层布局简单，先覆盖编译器能够直接发现的错误；符合用户当前的实现取舍。

**后续探索：**若加入运行时检查，应分别决定检查成本、静态消除、可恢复接口及不可返回故障处理；Hosted、内核与虚拟机可需要不同处置。客户机非法地址验证和宿主数据结构错误仍须分别建模，但当前不为数组强制设计 panic 或宿主退出行为。

### BD-16：结构体布局与比较（已接受，空结构体为 0 字节）

**已确定：**首个目标采用小端字节序、自然对齐，按声明顺序安排字段，每个字段向上对齐，结构体对齐取字段最大对齐，总大小向上补齐。不自动重排字段，首版不提供 packed/位域/自定义对齐。

```text
struct Layout {
    a: u8;
    b: u64;
}
// a 偏移 0，b 偏移 8，sizeof=16，alignof=8
```

整数/浮点基本类型对齐取各自的 1/2/4/8 字节自然对齐，数据/函数指针为 8 字节对齐。空结构体取大小 **0**、对齐 **1**；零长度数组大小为 0、对齐取元素对齐，这两项不默认声称可映射到普通 C 结构体成员。

结构体和数组首版不提供自动 `==`；显式逐字段或库比较，不按填充字节 memcmp 判断相等。

**理由：**便于 FFI、调试和推算布局；字段值与填充表示分离。普通聚合的对齐依据参见 [Microsoft x64 类型与布局说明](https://learn.microsoft.com/en-us/cpp/build/x64-software-conventions?view=msvc-170)。

**影响：**字段顺序影响空间；用户需手动优化排列。C 兼容还要求成员类型和 ABI 规则吻合，不因采用自然对齐就自动完成全部兼容。

#### 零大小类型的后果与配套（布局已接受，配套待审查）

- `struct Empty {}` 的 sizeof 为 0、alignof 为 1；数组元素步长按元素大小计算，因此 `[N]Empty` 的数据大小为 0。其逻辑元素数量仍为 N，不能从字节数反推数量。
- 按已接受布局算法计算，只有零大小字段的结构体也可能大小为 0；零大小字段不增加内容字节，但仍参与其类型的对齐计算。包含普通字段的结构体保持该字段的必要大小和对齐。
- 原始指针步进、两个指针的差值不能直接套用“除以元素大小”的实现。现有 BD-14 候选禁止对零大小目标执行原始指针算术；是否最终采用仍待审查，不能因修改 sizeof 就声称已经解决。
- 地址身份待定。建议不要保证不同零大小对象或元素地址不同，不为了唯一地址隐式给每个值增加内容字节；可选方案是禁止零大小值取地址，但会限制通用指针接口。
- 分配器需要明确处理零字节请求；建议库在类型层面识别零大小值，避免把零长度申请、释放或字节差值直接当作普通路径。复制/传参没有内容字节可搬运，但求值副作用不得因此删除。
- 空结构体、零大小成员/数组及其按值跨 C ABI 暂不宣称兼容；不通过填充成 1 字节暗中改变已接受的 sizeof。FFI 的具体限制或表示适配仍待单独设计。

零大小类型的数组、分配与指针步进确实需要特殊处理，其他语言也单独讨论这些边界，参见 [Rustonomicon：零大小类型](https://doc.rust-lang.org/nomicon/exotic-sizes.html#zero-sized-types-zsts)及[零大小容器实现](https://doc.rust-lang.org/nomicon/vec/vec-zsts.html)。本语言不自动继承其引用和指针规则。

#### DOP 定位的影响（设计说明）

现有显式数组、结构体、指针、模块函数、手动内存与稳定布局可以继续使用。DOP 首先影响数据组织与接口：批量处理连续元素，按访问模式选择 AoS/SoA，使用普通组合/索引/句柄表达关系；不要求所有类型都改为 SoA，也不要求先增加专用语法或向量后端。

BD-16 的不重排字段与此方向一致：布局由程序表达，编译器可在保持可观察行为时优化；不能以 DOP 为由悄悄修改 ABI。未来可探索容器、分配器、静态多态、显式非别名约束和 SIMD，但不在本次扩大自举范围。静态方法语法本身不必带来对象头或动态派发，是否提供仍应单独决定。

### BD-17：整数枚举（已接受）与 Payload 枚举（待审查）

**用户已确认并实现：**`E :: enum [(IntegerType)] { Name [= constant], ... }` 提供命名空间中的整数常量，E 在类型位置是底层整数别名；默认 i32、从 0 递增，显式初值后从前一值继续递增，重复名称/值及自动溢出报错。`enum(bit8/16/32/64)` 选择同宽无符号整数，从 1 自动逐位左移；成员声明禁止 0 和复合位，变量和计算结果仍允许 0 及任意整数组合。统一规则见[主规范第 9.3 节](language_spec_v0_1.md#93-普通枚举)，当前求值子集见[实现子集](parser_subset_v0_1.md#枚举与-switch-的当前实现)。

**撤回的候选：**普通枚举为独立值类型、必须声明零变体，以及未对应成员的整数值非法。成员就是底层整数，可计算、索引、复制及跨函数/C ABI 使用，不增加运行期值域检查或标签。不同枚举的相同底层整数可以混算；已有具体整数类型的转换边界仍保持显式。

Payload 枚举仍是未实现的独立长期目标，标签、布局、构造及访问方式需继续审查；不因整数枚举完成而视为支持，也不沿用已撤回的 match 解构提案。现有候选是不作隐式小对象/空指针标签优化，不自动承诺其 C ABI，尚未冻结为实现契约。

### BD-18：无标签 union（C 兼容基础子集已接受）

**实现记录（2026-11-17）：**用户授权直接实现简单 C 兼容 union，以下重叠布局、整块零初始化、单成员指定及合法表示的跨成员读取已合入[主规范第 9.2 节](language_spec_v0_1.md#92-无标签联合体)。当前调用/静态初始化和未支持语法以[实现子集](parser_subset_v0_1.md#无标签-union-的当前实现)为准；一般指针别名模型及 Payload 枚举继续单独审查。

**默认行为：**所有字段起始偏移为 0，大小取最大字段大小并补齐到最大字段对齐。union 零初始化清零整个 union 存储；不附加运行期有效字段标签。

指定初始化器至多选择一个字段，也可使用 `{}` 得到零存储。允许写入一个字段后读取另一个字段进行位重解释；结果必须具有目标字段类型的合法表示，并满足访问权限。非法 bool/enum 表示等不因来自 union 而变得合法。

**理由：**保持 union 作为真正的底层共享存储工具，区别于自动维护标签的 Payload 枚举。

**影响：**没有自动有效字段检查；填充及超出较小字段写入范围的字节不得被假定为某个新值，除非已明确写入/初始化。需要可验证的变体分派时应使用 Payload 枚举。

### BD-19：条件、循环与退出（已接受）

**实现记录（2026-11-16）：**已接通解析、语义、CFG、常量解释器和 Windows x64 输出，原生测试覆盖各类循环、最近退出目标及短路副作用。for 头部详细范围、局部作用域、返回路径的当前保守策略见[基础编译原型](parser_subset_v0_1.md)。

**已确定：**条件只接受 bool，`if/else` 与各类循环是语句。保留 `while`、`loop`、`do...while` 和 C 形状的 `for (init; condition; step)`，省略 for 条件表示 true。循环不产生值，首版无标签 break/continue。

各控制结构中显式出现的条件必须为 bool，指针判断使用显式比较。本条全部接受。完整 EBNF 与 for 初始化/迭代项的细节见对应章节。

所有控制体必须使用花括号，即使只有一条语句或为空也不省略；换行和缩进不决定控制体归属。`else if` 可直接连接下一条件分支，各分支体仍为显式块。

`continue` 对 while/do 转到条件检查，对 for 先执行 step 再检查条件，对 loop 回到开头。break 退出最近循环；return 退出当前函数，经过 BD-20 的作用域清理。

**理由：**保持原草案的控制流集合，避免引入额外的循环值和控制目标规则。

**影响：**不支持跨多层循环跳转时，需要辅助函数或显式状态；以后增加标签不必改变已有循环含义。

### BD-20：defer

**已接受并实现（2026-11-18）：**每个词法作用域逆序执行已登记的清理。块和直接调用均可带 bool 条件，条件与调用实参在清理时求值。外层 `return` 先求值，再执行退出清理。语法及退出目标规则统一见[语言规范第 8.2 节](language_spec_v0_1.md#82-defer)。

**理由：**实现显式资源清理，不引入异常展开运行时或隐式析构系统。

**影响：**资源变量后续改变会影响清理目标；要清理旧值需先保存到单独的普通变量并确保不再改写。若改为登记时捕获，需要明确复制成本和引用关系。

#### 其他语言的设计对照（信息性，非新增已接受规则）

| 语言 | 执行边界 | 延迟内容与求值时机 | 其他设计 |
| --- | --- | --- | --- |
| Go | 当前函数返回，含 panic 展开 | 函数值和实参在执行 defer 语句时求值并保存，调用延后，逆序执行 | defer 闭包内部读外部变量又是另一种行为；循环内可以为同一函数累积多次调用 |
| Zig | 当前作用域退出 | 延迟表达式退出时执行，逆序；未走到的 defer 不执行 | 提供仅在错误返回路径执行的 errdefer，defer 内禁止 return |
| Swift | 当前词法作用域退出 | 延迟代码块退出时执行，同作用域逆序 | 正常控制转移及抛错离开作用域时执行，禁止由 defer 体向外转移控制 |
| D | 当前作用域退出 | scope guard 的语句/代码块退出时执行，逆序 | scope(exit)、scope(success)、scope(failure) 分别区分退出、正常退出及异常展开 |

来源：[Go 规范：defer](https://go.dev/ref/spec#Defer_statements)、[Zig：defer](https://ziglang.org/documentation/master/#defer)、[Zig：errdefer](https://ziglang.org/documentation/master/#errdefer)、[Swift：defer](https://docs.swift.org/swift-book/documentation/the-swift-programming-language/statements/#Defer-Statement)、[D：scope guard](https://dlang.org/spec/statement.html#scope-guard-statement)。

**对本语言的应用：**循环体每轮独立清理，编译器将清理降低到作用域退出边上。所需存储与控制流成本见[实现子集](parser_subset_v0_1.md#延迟清理的当前实现)。

Go 的“先保存调用实参”和本语言已确定的“退出时求值”分别适合不同需求：前者固定当前资源或数值，后者不隐式增加实参快照。采用当前规则时，释放当前资源可使用单独保存且不再改写的普通变量，避免延迟清理随可变绑定指向新资源。只复制指针也不会复制其目标对象。

语言不提供异常与异常展开已确定。首版仍不建议增加 errdefer、成功/失败 scope guard 或 panic/recover。当前错误处理采用普通返回值或错误码，条件清理由源码提供 bool 表达式。

#### 显式代码块边界（已接受）

分支与循环的代码体使用 `{}`，包括单语句和空体。换行和缩进不决定语句归属。

- `if`、`else`、`while`、`for`、`do`、`loop` 的代码体均为显式块。
- `else if` 保留为已接受的链式条件分支语法，每个条件分支体仍必须为块；独立 else 后必须为块。它不是允许 else 接收任意裸语句的规则。
- `defer` 使用显式块或单个以分号结束的直接调用，见 BD-20。
- 函数定义和块形式的 #run 延续其显式代码块规则；已有 #run 表达式属于表达式操作，不是省略代码体括号。
- 省略 for 条件是独立的头部规则，不表示循环体可以省略块；空循环体必须写 `{}`。

**理由：**显式块直接界定代码体的范围和词法作用域。直接调用形式的 defer 使用当前作用域，调用语句由分号结束。

**影响：**早返回和单条循环体仍需写一对花括号。单次清理可使用直接调用形式。

### BD-21：switch（取代已撤回的 match）

**用户已确认并实现：**使用语句式 switch，选择值只求值一次；整数 case 强制编译期求值，重复值报错，default 可选且至多一个。非空 case 默认结束，连续空标签共享后续分支；`#through;` 在非末尾分支结尾显式进入下一分支。case 不强制 `{}`，作用域独立，可用任意嵌套 `{}` 增加词法作用域。break/continue 的目标规则统一见[主规范第 8.3 节](language_spec_v0_1.md#83-switch)。

撤回 match 表达式、模式/守卫/解构、分支结果类型及穷尽性提案。首次实现采用比较链和已有 CFG 跳转；不增加标签、运行期 case 求值或通用匹配运行时，也不宣称已有跳转表或最优分派。

### BD-22：函数与名称解析

**默认行为：**顶层声明顺序无关，支持递归/互递归；局部绑定先声明后使用，初始化器不能引用自身。每个模块首版采用统一的顶层名称空间，函数、类型、全局与模块别名不能重名；局部允许遮蔽其他局部，但不能遮蔽类型、模块名或关键字。

不支持函数重载、默认参数、隐式可变参数、闭包或泛型语法糖。void 函数用 `return;`，非 void 函数所有可正常到达的退出路径必须返回值；可证明不退出的路径无需 return。不确定的返回分析可以保守诊断。

**理由：**声明收集与表达式解析简单，防止调用处依赖复杂重载规则；已计划的编译期类型值和元编程继续单独设计。

**影响：**相同操作处理多个类型时需要不同函数名、编译期生成代码或后续泛型能力。统一名称空间比 C 的标签名称空间规则更严格。

### BD-23：模块身份、可见性与路径

**已确认部分（MOD-01）：**直接导入、`name :: import` 模块绑定、同一模块只加载一次、导入符号重名编译报错，以及私有名称依赖在定义模块中解析。规则与验证预期统一见[语言规范第 11 节](language_spec_v0_1.md#11-模块与名称空间)，此前默认文件名与可选 as 方案不再沿用。

**其余候选：**顶层默认私有，export 可用于函数、类型、普通全局变量与编译期常量。导出的结构体字段和枚举变体首版一并公开，暂不引入字段级可见性。导出接口所暴露的命名类型必须可公开访问，禁止隐式泄露私有类型。

**已确认补充：**导出普通全局变量共享同一存储、不含隐式原子操作；可变性、复制及存储归属统一见主规范第 11.2.1 节。模块最小子集已实现，完整初始化限制仍按 BD-24 独立审查。

模块身份采用文件系统解析符号链接/目录链接后的最终绝对路径，名称相等遵循实际文件系统规则，不简单将全部路径转为小写。不同硬链接路径视为不同模块。模块内相对导入以最终源文件目录为基准。

循环导入允许用于声明发现；循环的按值布局、常量或编译期执行依赖报错。源文件扩展名、标准库和包搜索规则仍不在本轮代为命名。

**理由：**模块不需要运行时加载，别名和可见性全在编译期处理；确定性的身份规则避免重复分析和平台大小写误判。

**影响：**符号链接位置与真实文件位置不同的项目必须按真实文件目录组织相对导入；硬链接会形成独立模块身份。若希望逻辑项目路径，需另设模块根配置。

### BD-24：全局初始化与显式启动

**默认提案：**首版普通全局变量可省略初始化，生成静态零值；编译期常量始终须显式初始化并求值成功。普通全局变量的显式初始化器也必须能够在编译期求值，结果可写入静态数据/重定位。局部普通变量允许运行期初始化；不再存在运行期 const 绑定。

需要文件、分配或其他运行期资源时，在 main 或用户显式调用的初始化函数中建立。语言不自动运行用户全局初始化函数，也不注册隐式退出清理。

**理由：**无隐式启动顺序、初始化状态位和析构注册表；跨模块常量依赖可以在编译期解决。

**重要影响：**这是对普通全局变量初始化能力的首版候选限制；编译期常量本身始终要求编译期结果。若希望全局直接调用运行期函数，需要设计顺序、循环、失败与启动成本，不能只放开语法。

**已授权实现的子集：**普通结构体全局已支持默认/花括号指定静态初始化，包含嵌套结构体和字段数组；标量叶子须可编译期求值，指针初值限 null，不生成运行期初始化调用。完整边界统一见[实现子集](parser_subset_v0_1.md#结构体的当前实现)，不将这次实现视为本提案全部接受，也不包含聚合常量、聚合调用/复制初值或静态地址重定位。

### BD-25：错误分类与可选检查

**默认行为：**类型错误、重复声明、缺少编译期常量初始化器等为编译错误。静态可证明的非法常量索引/转换应诊断；编译期实际执行的非法内存或数值操作必须停止并诊断。

默认运行期对非法原始指针内存访问、整数除零、非法移位、无效枚举和越界浮点转整数不保证结果、陷阱或清理；它们是未定义行为。内置数组已确认当前只有有限静态检查、无自动动态检查；未发现的运行期越界仍为非法访问，不承诺捕获或恢复，具体非法行为分类继续待审查。CPU 恰好产生异常不成为语言保证。

**后续探索：**若提供可选检查模式，可考虑溢出提示、边界、空值、对齐和枚举检查；此模式单独计成本，也不能承诺捕获所有原始指针错误。默认合法程序的结果不因诊断模式改变；BD-06 的整数环绕已经接受，诊断工具可提示但不能把它改成标准语义中的错误。当前数组运行期检查仍不属于实现要求。

库 I/O 和分配失败通过普通返回值或显式错误码报告，不隐式抛异常。检查失败的显式停止函数不执行异常展开，不保证 defer。

**理由：**将静态诊断与零开销运行路径区分，避免用“没有检查”掩盖未定义行为的真实后果。

**影响：**未定义行为不只是“可能崩溃”，还会影响编译器允许的优化。程序必须先满足定义域，才能要求不同优化阶段或编译期/运行期结果一致。

### BD-26：sizeof、alignof 与首轮 C ABI

**本轮确认与实现（2026-11-17）：**补齐 u64，sizeof/alignof 使用目标布局并返回 u64 编译期值，首轮只查询完整对象类型。规则统一见[语言规范第 7.5 节](language_spec_v0_1.md#75-sizeof-与-alignof)，void 返回与 C 可变参数调用已在后续增量实现；浮点及完整 C ABI 仍未完成。

**已确认与实现（2026-11-16）：**稳定 ABI 目标与 C 一致；`#extern(C)` 固定签名声明、字符指针及 puts 最小调用已实现。确定规则、已实现类型与尚未覆盖的 ABI 功能统一见[语言规范第 13 节](language_spec_v0_1.md#13-c-互操作与执行环境)。下述其余首轮类型范围继续作为候选，不代表 void/浮点/聚合等已经实现。

**默认行为：**`sizeof(T)`、`alignof(T)` 首版只接受完整对象类型，结果为目标平台布局对应的 u64 编译期值；不接受 void 和未定布局递归类型，不求值运行期表达式。

首轮 extern(C) 使用完整原型和固定参数，优先覆盖 void 返回、固定宽度整数、f32/f64 与指针。复杂聚合优先显式传指针，不先依赖 C 可变参数和 Payload 枚举按值 ABI；C 回调必须具有明确兼容的函数指针签名。

语言内部按值聚合仍保持 BD-12 的语义，不能为了简化 C ABI 把它改为引用语义。完整 Windows x64 C ABI 兼容目标继续保留，相关参数、返回、栈和展开元数据按 [Microsoft x64 调用约定](https://learn.microsoft.com/en-us/cpp/build/x64-calling-convention?view=msvc-170) 单独验收。

**理由：**自举所需接口可以明确且较小，不引入语言通用运行时；先把调用协议正确性和语言值语义分开。

**影响：**需要少量固定签名基础库/C 封装来避免首轮可变参数。自然布局不等于完整 ABI 兼容，首轮通过子集不能宣称完整兼容。

### BD-27：入口、基础库与默认运行依赖

**默认行为：**Hosted 程序提供唯一 `fn main() -> i32`，返回值成为进程退出码。参数、文件、输出和分配通过显式基础库/外部接口取得；不自动注入动态字符串数组或隐式堆分配。

Compiler Driver 与首个启动方案负责对接已选择的系统/C 启动方式，允许依赖 Windows/C 库；语言功能本身不强制一套独立 GC/异常/反射运行时。不设置会暗中注册清理器的全局对象模型。

**理由：**满足当前 Hosted 目标，保持调用和依赖可见；未来 Freestanding 可以替换启动接口。

**影响：**零额外语言运行时不等于当前立即脱离操作系统或 C 库；命令行接口的具体库函数仍待基础库契约确定。

### BD-28：#run 的基础求值边界

**本轮确认与实现（2026-11-18）。** `#run f()` 在编译期调用函数，可独立执行或将结果用于 `=`、`:=` 初始化器等表达式位置。`#run { ... }` 定义无返回值块，`#run -> Type { ... }` 定义用显式 `return` 产生结果的块，两者均保留定义。实现范围为独立调用和标量求值。聚合编译期内存、代码块执行及 AST 修改继续待实现，见[第 12.1 节](language_spec_v0_1.md#121-能力边界)。

**默认行为：**#run 按目标类型位宽、BD-06/07 的数值规则和目标布局执行；普通环绕在编译期也环绕，非法操作由编译器诊断。编译期分配和反射资源属于编译器进程，不成为运行期依赖。

首个基础求值器默认不开放任意 FFI、系统调用或外部文件副作用。运行期所需结果先支持可静态序列化的标量、聚合及 null/符号重定位引用；编译器宿主地址和临时 AST 句柄不能直接泄露成运行期指针。

**理由：**使跨阶段语义一致，避免宿主地址、环境和隐藏运行时依赖污染目标程序。

**影响：**开放编译期文件/系统能力应另定权限与可复现构建契约；这不是永久禁止该能力。浮点求值器仍须满足 BD-08 的舍入要求，不能直接把宿主默认算术当作规范。

### BD-29：完整 Comptime 与自举顺序的保留项

**当前处理：**继续保留任意 AST 读写和生成声明的目标，以及架构文档原有 M2 先于 M4 的路线。本版基础默认行为不擅自选择只追加 AST，也不把完整 Comptime 自动移到首次自举之后。

AST 修改的执行顺序、修改执行中函数的生效边界、重分析后是否重执行 #run、副作用事务与依赖循环仍需独立契约。该部分不声称已经实现可编码的完整默认调度模型。

**理由：**这些选择会改变语言核心能力和编译器架构，不能用基础规则提案中的一个临时约定偷换已有目标。

**不同路线的影响：**

| 路线 | 优点 | 代价 |
| --- | --- | --- |
| 完整可变 AST 后再自举（现有路线） | 第一轮验证元编程目标 | Stage 0 要先完成稳定身份、调度、失效与循环处理 |
| 基础自举后补完整 AST 修改 | 更早验证编译闭环 | 明确改变里程碑，首次自举不代表完整语言能力达成 |
| 首版只追加生成声明 | 调度较容易实现 | 必须明确这是阶段子集，不能声称已实现任意 AST 修改 |

## 5. 零开销验收建议

实现后按语义进行代码生成审查，而不是现在声称已达成性能保证：

1. 编译只有算术的程序，确认没有引入 GC、反射表、隐式分配或通用语言运行库。
2. 确认当前数组访问没有自动动态边界检查，并验证有限静态越界诊断；普通整数加法、显式窄化和原始指针检查按各自待审查规则验证。
3. 检查 #run 在编译期完成，产物中不残留求值器或 AST 调度器。
4. 检查编译期常量初始化不残留运行期求值或调度，不引入每对象可写性标志。
5. 检查 defer 与手写退出清理保持相同必要工作，不要求堆分配登记栈。
6. 比较手写标签/union 与 Payload 枚举，确认无额外隐含元数据；若以后加入受检数组，再与手写等价边界判断比较必要成本。
7. 验证零写入只在语义允许时消除，不以优化破坏默认零初始化。

## 6. 本轮未代为冻结的事项

本提案已经给出基本数值、内存、字符串和控制流的默认选择，但以下事项不能声称已完成：

- 正式语言名称与源文件扩展名。
- 完整且无歧义的 EBNF，以及与泛型/类型值相关的后续语法。
- 完整 AST API、Comptime 调度、修改生效、重执行和副作用契约。
- 完整 C ABI 覆盖、启动代码和基础库接口的实现验收。
- 用户对本版新增默认行为的逐项审查。

主规范中的“待定”在本轮表示“已有候选方案，仍待审查”，不是交给实现随意决定。
