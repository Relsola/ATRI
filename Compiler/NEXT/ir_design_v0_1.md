# Stage 0 IR 内部设计 v0.1

> 当前整数子集的内部实现契约，2026-11-16。不是语言语法标准；长期总体方向见[架构草案 §3.3](self_hosting_compiler_design_v0_1.md#33-ir-与优化器)，实际可执行范围见[整数编译原型](parser_subset_v0_1.md)。

## 表示

`AtriIRProgram → AtriIRFunction → AtriIRInst[]`，函数另有实参索引数组。函数索引引用调用目标，指令索引引用函数内的值，不用源码名称做优化期名称解析。IR 保存必要的名称/源码区间用于 Dump 和诊断，因此输入源码必须保持存活。

当前每个函数只有一个 entry 基本块，值类型显式为 `ATRI_IR_I32`。指令包括 param、const、unary、binary、call、return；NOP 标记优化删除的指令。除 return/NOP 外，每条指令产生一个值，操作数引用之前产生的值。常量用 uint32_t 保存目标位模式，借助显式有符号解释处理除法和 Dump，不依赖宿主 C 的有符号溢出。

当前标量无取地址/控制流，局部绑定可直接映射到 IR 值，let 重新赋值更新映射；const 不需要额外运行期对象。这不冻结将来可取地址变量的表示。后续加入对象存储、load/store、字段/元素地址及 CFG 时，必须扩展表示和不变量，不能把这个单块值表示宣称为完整 SSA 框架。

## 前端降低

第一遍发现并检查所有函数签名、重复定义和支持类型；第二遍分析函数体。所有调用在第二遍通过已经收集的签名检查，因而没有前向声明要求。局部名称当前顺序可见，调用参数先按顺序产生值，再构造 call；嵌套调用的实参范围独立保存。

名称与类型检查当前和 IR 降低在同一阶段完成，没有额外构建 Typed AST。所有函数体均检查，不能因为 main 已折叠为常量而跳过错误的函数。编译期执行和 AST 修改尚未实现；未来必须在相关程序部分语义稳定后才进入可优化 IR。

## 优化

1. 将源语言局部绑定映射到已有值，传播已知值；不因 const 声明就强制执行未知调用。
2. 对已知 i32 操作数折叠，采用本轮暂用的 BD-06 候选数值语义。
3. 在 -O1 下克隆适合的无调用小函数，将形参值替换为实参值，并在克隆时继续折叠。
4. 逆序标记 return/call 的依赖，删除无用纯计算；未内联调用保留，避免擅自删除递归/不终止行为。
5. 多轮处理叶函数，支持定义顺序无关的短调用链；递归环保留调用。

当前内联启发式为：被调函数没有剩余 call、活跃指令不超过 64、原始指令数不超过 4096；调用者增长有预算，多轮最多 64 次。它是可调整的实现策略，不是语言对内联的保证。

`-O0` 不内联，但仍实施本地折叠和死指令消除，不等于逐条还原源码的执行跟踪模式。尚无跨函数可达性删除、通用 CSE、循环优化、别名分析或寄存器分配。

示例优化前：

```text
func @main() -> i32 {
entry:
    %0 = const i32 1
    %1 = const i32 2
    %2 = call i32 @add(%0, %1)
    ret i32 %2
}
```

优化后：

```text
func @main() -> i32 {
entry:
    %0 = const i32 3
    ret i32 %0
}
```

## Verifier 与后端边界

Verifier 在降低后、优化前后、机器输出前运行，检查类型、参数编号、操作符、操作数在定义之后使用、call 目标/参数数量/实参范围、return 值，以及 entry 基本块必须以唯一的 return 终结。它检查内部结构，不代替前端语言合法性检查。

后端处理目标寄存器、栈槽、栈帧、调用约定和汇编语法。IR 中没有 EAX/RCX 等机器寄存器；main 返回常量 3 时，后端直接选择 `mov eax, 3; ret`。非恒定中间值当前先存栈槽，后续再增加寄存器分配；该实现成本必须通过汇编和执行测试持续审查。

新增类型、控制流或内存指令时，应同时修改 IR 定义、Verifier、Dump、优化器、后端和有行为意义的测试，避免某个阶段静默忽略新指令。
