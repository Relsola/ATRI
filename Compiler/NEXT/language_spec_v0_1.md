## 1. 范围与规范约定

本文定义语言对使用者可见的词法、语法、类型和执行行为，包括编译期执行、模块与外部函数互操作。编译器的实现语言、AST 内部结构、IR 设计、优化算法、汇编器和链接器选择由架构文档规定。

本文从原设计草案抽离，不将推荐方案自动升级为已确定规则。用户已授权先拟定基础默认行为再审查；新增候选集中在[基础默认行为与设计取舍：审查稿 v0.1](language_defaults_review_v0_1.md)，本规范仍是统一入口。

审查稿为数值、初始化、内存、字符/字符串、控制流和模块等提供完整的一组候选默认行为，每项包含理由和重大替代方案。本文的待定项已有提案时，仍待用户审查；不得将候选方案当成已确认规则。用户已确定规则优先，审查后再将相应条款合入本规范正文。

| 标记 | 含义 |

## 2. 语言模型与实现范围

### 2.1 基本模型

**已确定：**

- 语言为强类型、命令式、偏底层的通用编程语言。
- 核心定位为面向数据编程（DOP），优先服务显式数据表示、布局控制和批量处理，以此指导语言与基础库设计。
- 采用类 C 语法，优先保证语义明确和可解析性。
- 区分运行期执行和由 `#run` 显式要求的编译期执行。
- 顶层声明顺序无关，不要求使用者编写前向声明。
- 正式方向包含完整目标平台 C ABI 兼容，以及能够访问、构造和修改任意 AST 的编译期元编程。
- 运行时遵循零开销设计方向；对等价手写底层代码的成本定义、原始指针访问与内置数组检查的区别及必要语义成本的边界，见默认提案 BD-00/15。
- 语言不提供异常机制，不引入 throw/catch 或语言异常栈展开。编译诊断、普通错误返回以及目标硬件/客户机异常按各自契约处理。

**建议：**首版采用手动内存管理和显式错误处理，不引入所有权检查、借用检查或强制 GC；不提供语言异常已由用户明确确认。

### 2.2 平台与阶段

首个实现目标是 Windows x86-64，首版按 Hosted 环境设计。Freestanding 和其他目标平台属于后续扩展。

语言的完整目标能力与首次自举所需的实现子集应分别记录。能够自举只说明实现足以编译编译器自身，不自动说明已实现本规范的全部能力。

核心可自举子集尚未冻结，候选范围见附录 A。原路线中的 M0 至 M5 是工程里程碑，不是独立的语言版本。

### 2.3 DOP 定位对当前设计的影响

**已确定的方向：**面向数据是语言核心定位，不以 OOP 对象体系作为设计中心。现有结构体、数组、显式指针、模块函数与零开销方向继续沿用，不据此推翻前后端架构。

**设计影响与后续建议：**

- 保持结构体表示与内存成本可见，按已接受的 BD-16 保留声明顺序布局，不为“面向数据”自动重排可观察字段或改变 C 布局。
- 以普通数据结构和批量处理函数组织接口，组合与索引/句柄可作为后续基础库设计手段；不隐式引入对象头、继承关系或虚调用。
- 数组的完整类型/值语义与基础容器接口继续优先审查。数据访问模式可以选择数组内嵌结构体（AoS）或将字段分别放入数组（SoA），两者的适用性由算法与测量判断。
- 数据组织与算法实现相对独立，编译期代码生成可在以后帮助构造批量接口；不要求第一轮先实现 SIMD、自动向量化或专用 SoA 语法。
- 不从 DOP 一词额外推导“所有数据不可变”“禁止封装/方法语法”或“所有数据都必须改成 SoA”；这些若有需求仍需单独审查。

以下只示意数据组织，不新增数组或方法规则：

```text
struct Position {
    x: f32;
    y: f32;
}
positions: [1024]Position; // AoS：每个元素包含 x/y

struct PositionColumns {
    x: [1024]f32;
    y: [1024]f32;
}                            // SoA：分别保存 x 列和 y 列
```

AST、链表和其他图状数据仍可按真实访问需求使用指针或索引。DOP 是设计取向，不承诺仅改变语法就提高缓存效率或性能。

## 3. 词法结构

### 3.1 已出现的词法元素

以下是草案已使用的拼写清单，不代表完整的保留字或 Token 定义。

| 类别 | 草案中的拼写 |
| --- | --- |
| 声明与类型 | `fn`、`struct`、`union`、`enum`；绑定通过 `name: Type` 引入 |
| 空指针字面量 | `null`，根据指针上下文定型；不是整数 0 |
| 控制流 | `if`、`else`、`switch`、`case`、`default`、`loop`、`while`、`for`、`do`、`break`、`continue`、`return`、`defer` |
| 编译器指定能力 | `#run`、`#insert`、`#keyword`（插件内）、`#extern(C)`、`#through` |
| 内置运算符 | `cast`、`sizeof`、`alignof` |
| 模块 | `import`、`export`、`name :: import`（见第 11 节） |
| 内置类型名称 | `bool`、`i8`、`i16`、`i32`、`i64`、`u8`、`u16`、`u32`、`u64`、`isize`、`usize`、`f32`、`f64`、`void`；首版范围和待定边界见第 5 节 |
| 其他已展示拼写 | `->`、`#`、`&`、`*`、`::` |

**已确认并实现：**编译器指定能力使用单个 `#` 前缀，包括 `#run`、`#insert`、插件内的 `#keyword`、`#extern(C)` 和 `#through`；`#` 与能力名称之间可有普通空白/换行，例如 `# through;`。未知名称报错，旧裸 run 和 `[[extern(C)]]` 不再兼容；`##extern(C)` 也不是此语法。`#` 不统一决定执行阶段：#run 强制编译期执行，#extern 指定外部调用，#through 指定运行期控制转移。cast/sizeof/alignof 保持运算符写法，import/export/defer 仍为各自语法，不迁移为编译器指令。

### 3.2 待定规则

在 Lexer 实现冻结前，需要确定：

- 源文件编码、换行和非法编码处理。
- 标识符字符集、大小写敏感性、保留字与保留名称。
- 空白、行注释、块注释及块注释是否允许嵌套。
- 整数字面量已按第 5.4 节确定；浮点字面量、指数与未来类型后缀继续待定。
- 字符与字符串字面量、转义、编码、终止符和对应类型。
- 布尔字面量和空指针值的拼写与类型。
- 已有运算符集合与优先级见第 7 节；未来浮点小数点与 `...` 等词法边界另行补齐。

示例中的 `//` 注释仍只展示意图；当前最小字符串字面量范围见第 5.5 节和实现子集。

## 4. 语法框架

### 4.1 已确定的形式

```text
fn add(a: i32, b: i32) -> i32 {
    return a + b;
}

a: i32 = 10;
b: i32 := 20;
c: u8 = cast(u8, a);
```

- 函数形式为 `fn name(parameters) -> ReturnType`。
- 参数、局部绑定及命名字段统一采用 `name: Type`，名称与类型通过冒号分隔；不再采用 `Type name`。函数返回类型仍放在 `->` 后。
- 普通变量写作 `name: Type [= expression];`，编译期常量写作 `name: Type := expression;`；不使用 `let` 或 `const` 声明关键字。
- 普通类型之间的转换显式书写为 `cast(T, expression)`。

### 4.2 不完整的 EBNF 片段（示意）

本节仅整理草案已有的声明形状，不作为完整 Parser 的验收依据。引号内为终结符，`[ ]` 为可选项，`{ }` 为重复项；未展开的非终结符尚待定义。

```ebnf
function-definition = "fn", identifier, "(", [parameter-list], ")",
                      "->", type-expression, block ;
parameter-list      = parameter, { ",", parameter } ;
parameter           = identifier, ":", type-expression ;
binding-declaration = variable-declaration | constant-declaration ;
variable-declaration = identifier, ":", type-expression,
                      ["=", expression], ";" ;
constant-declaration = identifier, ":", type-expression,
                       ":=", expression, ";" ;
```

普通变量省略初始化表达式时执行默认初始化；标量默认零值，结构体字段声明默认值的优先规则见第 9.1 节；编译期常量必须显式提供可在编译期求值的初始化表达式。各类型零值的定义见第 6.1、10 节，初始化器表达式的完整语法仍待补齐。

**名称空间边界：**`::` 继续表示模块限定访问，例如 `math::add(1, 2)`；不将 `name :: expression` 同时定义成常量声明，避免它与函数体内的限定调用产生二义性。类型推导的常量/变量写法均待定，不靠空格区分语义。当前 `:=` 是完整的双字符符号，不能拆成 `: =`。

### 4.3 待补齐的语法

- 完整的顶层声明、局部声明与语句产生式。
- 类型表达式，尤其是函数类型、指针、数组的组合。
- 已确定的运算符优先级、结合性、赋值和复合赋值见第 7 节，完整 EBNF 仍须汇总。
- `cast(Type, expression)` 内的类型/表达式文法，以及未来转换模式的扩展规则。
- `for` 初始化/迭代项的完整语法、尾逗号和空语句等规则；C 形状 for 及首版无标签控制流已由 BD-19 确认。
- 结构体 `{.field = expression}` 初始化器的完整语法、其他聚合值构造、字段访问、枚举变体构造和模式解构。
- `#run` 表达式、代码块及其允许出现的位置。
- 属性、模块可见性和程序入口的具体语法。

### 4.4 当前已实现的基础编译子集

Stage 0 已实现 `name: Type` 参数/普通变量、`name: Type := expression` 编译期常量、整数/布尔表达式与直接函数调用，包含 i32/i64/bool/*i32 的名称/类型检查、前向函数引用、编译期分支/循环/递归、多基本块 CFG、局部对象 load/store、直线代码传播/折叠/内联及 Windows x64 汇编输出。BD-19 的条件、循环、break/continue 已实现，控制体强制使用花括号。

完整实现范围见[基础编译原型](parser_subset_v0_1.md)及[指针子集](pointer_subset_v0_1.md)，内部契约见 [IR 设计](ir_design_v0_1.md)。当前支持固定数组、无标签 union、多级数据指针、`?:`、`#run` 函数调用、整数/数据指针 cast、sizeof/alignof、void/opaque、C 可变参数调用、整数枚举、switch 与 defer。第 12 节规定编译期块、注解和 AST 接口。浮点运算及指针整数转换/排序仍待实现。

## 5. 类型系统

### 5.1 内置类型

**已确定的方向：**

| 类型 | 含义与边界 |
| --- | --- |
| `bool` | 大小/对齐均为 1 字节，合法表示 0/1，默认 false；不与整数或指针转换 |
| 字节字符 | 不另设 char 类型；使用 u8/i8，单引号字节字面量固定为 u8，见第 5.5 节 |
| `i8/i16/i32/i64` | 固定位宽补码整数；首个目标大小/自然对齐为 1/2/4/8 字节；运算见第 7.2 节 |
| `u8/u16/u32/u64` | 固定位宽无符号整数；大小/自然对齐与对应有符号类型相同；运算见第 7.2 节 |
| `f32/f64` | 计划支持的浮点类型；精确格式、舍入和特殊值行为待定 |
| `void` | 表示无返回值，不能声明对象/字段/数组元素；允许 `*void`，其目标不能直接访问 |

不提供传统含义模糊的 `int` 类型。

**原草案建议：**`isize` 和 `usize` 分别为宽度与目标平台指针相关的有符号和无符号整数。首个目标上均为 64 位。

**修订讨论（2026-11-15，TYPE-03）：**用户提出当前可能不需要这两个类型。候选方案是首次实现暂不提供，以固定宽度整数表达所需计算；若采纳，应同步确定 `sizeof`、`alignof`、长度、索引及 C ABI 大小参数的类型。暂缓首版支持不等于永久排除平台相关整数类型。此项尚未冻结。

**当前首版方案：**首次 Windows x86-64 实现继续暂缓 `isize/usize`。本轮补齐 u64，并确认 sizeof/alignof 的结果为 u64；缓冲区长度/容量和分配大小采用 u64、有符号偏移/差值采用 i64 的其余方案仍按 TYPE-03 审查。当前数组索引接受八种定宽整数，单引号字节字面量可直接索引；原始指针偏移仍限 i32/i64。不将所有平台的大小类型永久固定为 64 位。

### 5.2 复合类型

语言方向包含指针、数组、函数类型、结构体、无标签联合体和枚举变体。

```text
*i32       // 指针示意
[16]u8     // 定长数组示意
```

函数类型与函数指针的拼写、类型等价性、递归类型的合法性、类型别名及限定规则待定。

### 5.3 类型值

**建议：**提供内置 `type` 或等价机制，允许编译期程序表示和操作类型。

**待定：**类型值能否存储、传递和比较，是否仅能存在于编译期，以及如何与 AST 反射配合。此项不表示已经确定泛型语法或完整泛型系统。

### 5.4 类型转换与字面量

**已确定（BD-03，2026-11-17）：**禁止普通类型之间的隐式转换。已定型整数不因接收变量或返回类型而改变类型；两个普通算术/位运算操作数必须同类型，移位数量例外。显式转换采用 `cast(T, expression)`，规则见第 7.3 节。

声明、字段、参数、返回值或另一个已定型操作数可以为未定型整数字面量及纯字面量算术提供上下文；无上下文时默认 i32，超范围报错，不自动选更宽类型。定型后按目标位宽运算，编译期不改为无限精度。允许直接书写各有符号最小负值。

整数字面量支持十进制、`0x/0X` 十六进制和 `0b/0B` 二进制。`_` 只能出现在两个有效数字之间，不可连续、位于末尾或紧跟进制前缀；暂不提供类型后缀。前导零仍表示十进制，例如 `010` 为 10；本轮未加入八进制整数形式。非十进制字面量也按数值检查范围，`x: i8 = 0xFF;` 报错；需要位模式转换时使用 `cast`。

```text
a: u16 = 0xFF00;
b: u8 = 0b1010_0101;
c: u64 = 1_000_000;
d: u16 = a + 1;
e: u32 = cast(u32, a);
```

单引号字节字面量具有确定的 u8 类型，不随上下文改为 i8/i32；需要其他类型时使用显式 cast。浮点定型、函数类型等价和其他类型推导仍待审查。

### 5.5 字符与字符串

**已确认（2026-11-16，TEXT-01）：**字符指针与目标平台 C 的 `char *` 保持一致，具体含义由本节及第 13 节定义。语言沿用前缀拼写 `*u8`；C 原型中的 `char *` 是对应的边界类型，不另引入后缀指针语法。

**已确认：**内置 `string` 类型整体暂缓，待用户继续考虑；这一决定同时适用于借用视图和拥有型内置类型，不永久排除以后加入。以下规则定义字符存储和指针接口，不隐式引入字符串容器。

#### 5.5.1 字符表示与目标平台

**已确定并实现（2026-11-17）：**不再提供内置 char 类型及其指针或兼容别名。8 位数据使用 u8/i8；单引号字节字面量固定为 u8，参与普通字节算术、比较、位运算、移位和索引，不引入 C 的整数提升。

字节字面量与字符串共享转义规则，解码后必须恰好一个字节。`'A'` 为 u8 的 65，`'\xff'` 为 255；空字面量、多字节字面量、`'中'` 拒绝。`'b'-'a'` 的类型为 u8、值为 1，可直接作为数组索引；`'a'-0` 也合法。负的字节差遵守 u8 环绕规则；需要有符号或更宽差值时先显式转换两个操作数。

```text
letter: u8 = 'a';
index: u8 = 'b' - 'a';
signed: i8 = cast(i8, '\xff');  // -1
```

首个目标的 u8/i8 大小与对齐均为 1 字节，数据指针大小/对齐为 8 字节。u8 的无符号解释不随目标 C 的 plain char 配置变化。C plain char 的标量参数/返回必须按所选目标映射：当前默认 Windows x64 为 i8；unsigned char/uint8_t 为 u8，signed char/int8_t 为 i8。字节字符串通过 *u8 对接 C char 指针地址，不隐式转码或改变正文位模式；完整映射见第 13.1 节。

Unicode 码点与字节分开：字符串普通文本采用 UTF-8，一个可见字符可能占多个字节。当前不新增 Unicode 字符类型或解码运行时，内置 string 继续暂缓。

#### 5.5.2 指针值、空值与所有权

`*u8` 是只保存一个地址的普通数据指针，不携带长度、容量、编码标签、分配器、引用计数或所有权。赋值、传参和返回只复制指针值，不复制目标字节，不延长目标生命周期，也不隐式分配、释放或添加析构操作。

`null` 表示不指向字符对象的空指针，按 `*u8` 上下文定型；普通整数 0 不隐式成为指针。省略普通指针变量的初始化器时得到 null。null、值为 0 的终止字节（NUL）和空字符串分别表示指针状态、数据内容和文本长度，三者不得混同。空字符串字面量 `""` 指向包含一个零字节的静态对象，不是 null。

C 函数返回 `char *` 不自动表示调用者获得所有权或可写权限。返回值可能指向静态、借用、可复用或新分配的存储，具体寿命、写权限和释放方式必须由该函数的接口契约明确；只复制指针不能替代这些契约。将地址传给 C 也不自动允许对方在对象失效后继续保存或访问。

#### 5.5.3 字节缓冲区、零结尾字符串与编码

字符指针可以指向没有终止零的字节缓冲区。只有调用要求 C 字符串的接口时，才必须提供从该指针开始、在有效可读存储范围内包含终止零的连续字符序列。使用“指针加显式长度”的接口时，应按该接口检查长度、容量和可访问范围，不额外假定存在终止零。

零结尾接口以遇到的第一个零字节结束；字符串长度按此前的字节数计算，不包括终止零，不按 Unicode 码点或用户可见字符计数。指针不保存该长度，`puts` 一类接口不会据此知道底层对象的全部容量。内嵌零之后的数据仍可存在于缓冲区中，但不会被同次零结尾读取包含。

普通源码字符串字面量采用 UTF-8 字节；`*u8` 类型本身不保证所指数据为合法 UTF-8。C 库或操作系统接口所需的编码由其接口规定，跨 C ABI 传递指针不执行转码、不插入 BOM，也不自动适配终端代码页。`wchar_t *`、UTF-16/UTF-32 缓冲区不是 `*u8` 字符串的替代拼写，转换编码需要显式操作。

#### 5.5.4 字符串字面量

当前最小字面量使用双引号，表达式类型为 `*u8`。普通文本保留源码 UTF-8 字节，转义解码得到 N 个字节后，额外附加一个零字节；静态存储大小为 N+1 字节，即使解码数据末尾已经有零，也仍附加终止零。

| 字面量 | 按顺序存储的十六进制字节 | 零结尾接口看到的字节数 |
| --- | --- | --- |
| `""` | `00` | 0 |
| `"abc"` | `61 62 63 00` | 3 |
| `"a\0b"` | `61 00 62 00` | 1 |
| `"你好"` | `E4 BD A0 E5 A5 BD 00` | 6 |

字面量具有静态存储期，其指针在程序运行期间有效，允许由函数返回；不因离开函数而销毁目标对象。字面量内容不可修改，包括其终止零；即使当前指针类型写作 `*u8`，也不能据此取得字面量的写权限。当前后端使用只读数据区，语言不承诺对非法写入进行静态诊断或产生特定运行期陷阱。

相同或可共享的字面量允许合并，是否共享存储不作为内容相等的依据；代码不能依赖不同出现位置必定具有不同地址。若需要可写文本，必须显式取得可写缓冲区并复制数据，不能通过指针赋值或改写 C 声明把字面量变成可写对象。

**已确定并实现（2026-11-17）：**字面量采用 ATRI 自身的解析规则，C 兼容指最终字节表示、终止零与调用边界，不要求兼容全部 C 源码解析。

- 支持 `\0`、`\n`、`\r`、`\t`、`\a`、`\b`、`\f`、`\v`、`\\`、`\"`、`\'`。
- `\xHH` 固定读取两位十六进制数字，表示一个原始字节；缺少数字或数字非法必须报错，后续字符不被吞入。例如 `"\x41B"` 为字节 41 42，再附加终止零。
- 不支持八进制整数或八进制转义。`\0` 是独立的零字节转义；`"\012"` 为 00 31 32，再附加终止零，`\123` 拒绝。整数字面量仍支持十进制、0x/0X、0b/0B；前导零没有八进制含义，0o/0O 前缀拒绝。
- `\b` 表示退格，不是二进制转义。未知转义、原始换行、源码 NUL 和未闭合字面量报错。
- Unicode 转义、相邻字面量自动拼接、反斜杠续行、宽/编码前缀与旧 C 预处理形式暂不提供。普通非 ASCII 文本直接按 UTF-8 保存；原始字节转义不保证有效 UTF-8。

#### 5.5.5 指针操作与访问契约

- `p + n`、`n + p`、`p - n` 的单位为 u8 字节元素，即当前目标的 1 字节。偏移接受 i32/i64，i32 先符号扩展到 64 位；不先在 32 位中缩放或截断地址。
- 指针移动只能在同一仍有效的对象/连续字符存储范围内，或形成其尾后地址；尾后地址不能作为实际读取或写入的位置。null 不允许参与指针算术，地址环绕不使越界移动合法。
- 两个 `*u8` 相减须来自同一存储（可含尾后地址），结果为可表示的 i64 字节距离。不能以两个独立对象在机器地址上恰好相邻证明相减合法。
- 同类型 `*u8` 的 `==`/`!=` 比较指针值，允许与 null 比较，不比较文本内容。当前不提供指针排序，也不提供整数/指针或不同目标指针的隐式转换。
- 实际读取必须满足目标存活、范围和可读权限；写入还必须满足可写权限。将只读对象交给承诺只读访问的 C 接口是允许的；交给将实际写入该对象的接口违反契约。

以上边界与 C 字符指针使用约定一致；指针加减的 C 依据可参见 [WG14 C 工作草案 N3047](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n3047.pdf)。默认不生成动态长度、空值、边界或生命周期检查；静态检查通过也不证明任意外部指针有效。一般原始指针的完整来源/别名/有效类型模型继续按 MEM-02、BD-14/25 审查，不因字符指针 ABI 表示相同就导入 C 的全部语言规则。

#### 5.5.6 当前实现与后续事项

字节字符使用现有 u8/i8 存储、指针读写、算术、比较、显式转换、常量/#run、布局和 C 调用。单引号为 u8，双引号为 *u8。Unicode 解码、目标只读指针、完整文本接口、函数指针和内置 string 继续待实现，详见[实现子集](parser_subset_v0_1.md#c-字符串与外部调用)。

每个非合并字符串字面量占 N+1 个静态字节，取得地址不引入运行期堆分配或正文复制。默认初始化、扫描终止零、CRT 缓冲和 I/O 仍有实际成本。字面量正文不可写；当前无目标只读类型，不承诺普遍静态拒绝通过别名/FFI 的非法写入。

**验证预期：**分别核对 u8 高位字节、字符运算/索引、固定两位转义边界、八进制拒绝、UTF-8/内嵌零/额外终止零和实际 C 调用；不把表示/ABI 通过当作完整文本系统或性能证据。

## 6. 声明、绑定与函数

### 6.1 绑定

**已确定：**

- 普通变量使用 `name: Type [= expression];`，允许重新赋值，省略初始化器时执行默认初始化，标量默认零值，结构体按第 9.1 节应用字段默认值。
- 编译期常量使用 `name: Type := expression;`，必须在编译期成功得到结果，不允许重新赋值。
- 不再提供仅表示运行期不可变绑定的 `const` 声明，也不使用 `let` 引导普通变量。
- 常量初始化可以调用能够在编译期执行的函数；无法求值、非法运算或超出编译资源限制时必须诊断，不能退回运行期初始化。
- 常量合法性不取决于优化开关或内联启发式。当前原型不允许常量初始化直接读取普通局部变量或函数参数，即使优化器恰好能推导出其值；被编译期调用的函数仍可使用其已知实参和内部可变局部变量完成计算。

**优化与编译期求值：**编译器可以对普通变量进行已知值传播、折叠和函数内联，但这些是保持语义的优化。`:=` 则明确要求在编译期得到常量结果；`examples/constants.ar` 中的 `add(1, 2)` 在 -O0 下也必须成为常量 3。`#run` 的长期目标仍包括更一般的编译期执行与 AST API，本轮整数常量求值不替代完整目标。

```text
a: i32;              // 默认初始化为 0
buffer: [16]u8;      // 所有元素默认初始化为 0
b: i32 := 20;
```

```text
missing: i32 :=;     // 编译错误：缺少初始化表达式
```

默认零初始化是语言层面的值规则；布局填充字节是否清零、动态分配的原始内存是否清零，不由这条绑定规则自动决定。union 的整块清零与读取合法性见第 9.2 节；枚举等类型的具体零值仍需分别定义，不能假设任意类型都具有合法的全零位表示。

编译期常量的值不可赋值；这不自动承诺其指针指向的对象始终不变。常量实体化、取地址、地址常量、聚合常量的可写访问及目标只读 API 仍待明确，不恢复此前的运行期 const/深度只读提案。

**待定：**各类零值的边界、局部与全局绑定的差异、全局初始化顺序、遮蔽、重复声明、可取地址性和生命周期。

### 6.2 函数

**已确定：**使用尾部返回类型，支持递归和跨文件调用；顶层函数不需要前向声明。

```text
fn add(a: i32, b: i32) -> i32 {
    return a + b;
}
```

函数指针是计划能力，具体类型和调用语法尚未完整定义。

**当前实现：**普通结构体使用按值复制、传参和返回，参数绑定保持只读；指针字段复制指针值，不复制目标对象。目标 C ABI 的寄存器或间接传递方式不改变语言值语义。其余聚合、完整复制/生命周期边界、void、重载、默认参数、可变参数及扩展入口继续审查。

### 6.3 名称解析

**已确定：**顶层声明顺序无关。

这不自动允许所有声明循环。例如递归函数、按值递归结构体、循环全局初始化和编译期依赖循环需要分别规定。

局部绑定是否必须先声明后使用、各名称空间是否分离，以及模块之间的可见性尚待确定。

## 7. 表达式与运算

### 7.1 求值与副作用

**已确定（BD-09，2026-11-17）：**普通操作数和实参从左到右、各求值一次；调用先求被调用对象，再依序求参数。赋值先确定左侧位置，再求右侧值，最后写回。复合赋值先确定左侧位置并读取旧值，再求右侧值、计算、写回，左侧位置只求一次。

`!`、`&&`、`||` 只接受 bool，结果为 bool；`&&/||` 短路，不执行不需要的右侧。指针判断必须显式比较，例如 `p != null`。`?:` 条件为 bool，两分支同类型（字面量可按上下文定型），仅执行所选分支。

优先级从高到低如下；普通二元层级左结合，前缀和 `?:` 右结合：

| 顺序 | 操作 |
| --- | --- |
| 1 | 限定名、调用、索引、字段及内置 cast/sizeof/alignof |
| 2 | 前缀 `+ - ! ~ & *`，编译期调用 `#run f(...)` |
| 3 | `* / %` |
| 4 | `+ -` |
| 5 | `<< >>` |
| 6 | `< <= > >=` |
| 7 | `== !=` |
| 8 | 按位 `&` |
| 9 | 按位 `^` |
| 10 | 按位 `\|` |
| 11 | `&&` |
| 12 | `\|\|` |
| 13 | `?:` |

掩码判断需写 `(flags & mask) == 0`。比较链需写成 `a < b && b < c`。赋值及复合赋值是语句，没有表达式结果。`#run f(...)` 的求值范围是整个调用，包括实参，见第 12.1 节。

### 7.2 数值运算与比较

**已确定（BD-06，2026-11-17）：**八种定宽整数支持一元 `+/-`、二元 `+ - * / %`、`~ & | ^ << >>` 及比较。除移位数量外，两操作数同类型；不采用 C 的普通整数提升。

`+ - *` 及有/无符号一元负号按 N 位取模，有符号结果按补码解释。一元 `+` 保持类型和值。`x: u8 = -1;` 得到 255，`i8` 的 127 加 1 得到 -128；普通字面量的正值幅度仍须符合定型范围，有符号最小负值例外见第 5.4 节。编译期和运行期采用相同定宽结果。

有符号除法向零截断，非零余数随被除数符号；无符号除余按无符号值计算。除零、有符号最小值除以或取模于 -1 均非法。必须执行的编译期路径报错；运行期默认不插入检查，非法运算行为未定义，不承诺硬件陷阱。

按位操作只处理类型位宽内的位；左移丢弃高位、低位补零，有符号右移补符号位，无符号右移补零。移位结果保持左侧类型；数量可为任意定宽整数（无上下文默认 i32），合法范围为 `[0, N)`。负数或数量达到/超过位宽非法，不以 CPU 掩码结果作为合法语义。静态可证的非法数量诊断，编译期仅执行实际路径；动态不增加检查。字节字面量按 u8 处理，也可作为移位数量。

复合赋值支持 `+= -= *= /= %= &= |= ^= <<= >>=`，保持目标类型，遵守对应运算规则；常量、只读参数和临时值不能作为目标。已有合法指针偏移允许 `p += n`、`p -= n`，仍仅接受 i32/i64 偏移并遵守指针访问契约。

同类型整数支持 `== != < <= > >=`，bool 支持 `== !=`，同类型指针支持 `== !=` 且可与 null 比较；**只有指针能与 null 比较**，裸 `null == null` 也缺少指针类型上下文。比较结果为 bool，bool/指针不排序，数组/结构体不自动提供整体比较。字节字符使用 u8 算术，无独立字符运算规则，见第 5.5.1 节。

**成本与实现要求：**普通环绕和位运算不引入默认检查、分配或运行时库；窄值可能需要截断/扩展，除法仍有机器成本。环绕语义禁止依赖“有符号永不溢出”的优化；显式求值顺序限制可观察副作用的重排。Stage 0 必须用无符号位模式实现目标算术，不能继承宿主 C 的未定义溢出行为。

### 7.3 显式转换

```text
c: u8 = cast(u8, a);
```

**已确定（BD-07，2026-11-17）：**显式转换采用 `cast(Type, expression)`，括号内使用 ASCII 逗号分隔类型和一个完整表达式。整数缩窄保留目标低位，扩宽按源有/无符号性做符号/零扩展；同宽转换保留位模式，再按目标类型解释。整数转换等价于数学值模目标位宽，不默认增加保值检查。例如 `cast(u8, 300)` 为 44，`cast(u64, -1)` 为最大 u64。首轮不开放 bool 与整数相互转换。数据指针之间的显式转换已随 C 互操作子集补齐，指针与整数转换继续单独审查。

**语法取舍：**C 式 `(T)*p` 需要名称解析才能区分转换与乘法；用户选择 `cast(Type, expression)`，避开该歧义及尖括号边界。`cast` 是内置语法，不解析为普通函数；目标类型与表达式由逗号明确分隔。未来转换模式可以另行设计，本轮不增加模式参数，也不兼容旧尖括号写法。

**当前实现：**支持八种定宽整数的两两显式转换，编译期与运行期共用相同位模式规则。源表达式沿用普通定型规则，cast 不把超范围字面量隐式放入目标类型；纯数字源表达式仍默认 i32，大数可先绑定为 i64/u64 再转换。完整范围及示例见[实现子集](parser_subset_v0_1.md#整数转换与布局查询)。

**C 互操作子集（2026-11-17）：**支持已有数据指针之间的 `cast(*T, pointer)`，包括 *void、*u8、*u8 和结构体/数组指针；只传递地址位模式，不生成边界/对齐/寿命检查。转换不改变底层存储的大小、对齐、访问权限或寿命，不允许借此修改只读字符串字面量。`cast(*T, null)` 为显式带目标类型的空指针；没有指针与整数/bool 转换。*void 与 opaque 目标不能解引用读写或做元素算术，须显式转换为合法完整对象目标后访问。编译期一般指针转换仍不支持；普通全局的静态 null 初始化沿用已有例外。

**待定：**浮点、枚举、指针整数转换、目标只读类型和未来显式模式。整数显式转换已接受，不据此冻结其他转换规则。

### 7.4 地址、解引用与索引

**当前实现（2026-11-18）。** `*T` 的目标可以是另一个数据指针，例如 `**u8`。可对指针变量取地址，并逐层解引用读写。每次 `*` 访问直接目标一层。直接目标为 void 或 opaque 时禁止解引用和指针算术。null 按指针上下文定型，普通指针省略初始化时得到 null。支持精确同类型的相等比较、按直接目标大小缩放的偏移与差值，以及显式数据指针转换。对可直接证明的空解引用和直接返回局部地址提供诊断。编译期指针操作、指针整数转换和排序仍待实现，详见[实现边界](pointer_subset_v0_1.md)。

**已确定的方向：**使用 `&` 获取地址、`*` 解引用，数组访问形式为 `arr[index]`。

**已确定（MEM-03）：**结构体成员访问必须在结构体对象表达式上使用 `.`；结构体指针先显式解引用，写作 `(*p).field`。不支持 `p.field`、自动指针追踪或 `p->field` 成员语法。`*p` 形成目标对象的访问表达式，不要求复制完整结构体。

```text
x: i32 = 10;
p: *i32 = &x;
buffer: [16]u8;
first: u8 = buffer[0];
```

依照已确定的默认零初始化规则，`buffer` 的元素均为 0，`first` 的值为 0。空指针、指针运算、索引类型、边界检查、对齐和存储有效性见第 10 节待定规则。

**已确定（ARRAY-01）：**当前数组采用目标 C 兼容的连续元素布局，编译器做有限静态越界检查，暂不生成运行时越界检查。可由常量与有限简单分析确定越界时给出编译错误；无法确定的动态索引允许编译，不要求先证明安全。静态检查通过不保证运行期访问合法，程序员仍须保证索引范围。

**已确定（ARRAY-01，2026-11-17）：**数组声明与元素列表初始化采用 `data: [N]u8 = {1, 2};` 形式；数组类型写作 `[N]T`，初始化器使用花括号包围、逗号分隔的元素表达式，按位置指定元素。例如：

```text
data: [2]u8 = {1, 2};
```

本次确认语法，不自动确定长度表达式的求值规则、初始化项少于或多于长度的处理、尾逗号、多维初始化、整体复制、参数退化或 `.len`/`.data` 接口。上述边界继续按 BD-15 审查。Stage 0 已实现固定数组和 u8/*u8；本轮采用的长度求值、缺省元素、值复制、索引和 ABI 限制仅作为原型边界，详见[实现子集](parser_subset_v0_1.md#固定数组的当前实现)，不自动冻结全部候选规则。

多维固定数组 `[M][N]T` 支持 `mat[i, j]`，逐层索引的含义与 `mat[i][j]` 相同。基表达式先求值，随后各索引从左到右各求值一次。可以只索引部分维度并得到子数组，也可以混用两种索引写法。各索引都须为定宽整数，并按对应维度做静态越界检查。索引列表至少有一项且不带尾逗号。

对元素类型表示兼容的正长度固定数组，存储为 N 个连续元素，大小为 N 乘以元素大小，对齐与元素一致，不附加隐藏长度/容量头部。零长度数组的大小/对齐已随 BD-16 接受，但不默认承诺其 C 兼容性；运行期长度、强类型数组的完整接口和值语义继续待审查。确认布局不自动接受 C 的所有数组退化和函数参数规则。

**后续探索：**动态边界检查、失败处置、可恢复接口和目标环境适配暂不作为当前实现要求。运行期非法越界不承诺被自动捕获，其精确非法行为分类仍由内存契约明确。详见审查稿 BD-15。

### 7.5 `sizeof` 与 `alignof`

**已确定：**提供语言内置操作 `sizeof`、`alignof`。

```text
bytes: u64 = sizeof(Vec2);
alignment: u64 = alignof(Vec2);
```

**本轮确定并实现（2026-11-17）：**首个 Windows x86-64 子集中，`sizeof(T)` 和 `alignof(T)` 的结果为 u64 编译期值，分别使用目标类型的字节大小与对齐，不读取宿主对象，也不生成运行期查询。首轮只接受完整对象类型，支持当前标量、指针、数组和结构体；指针大小不依赖目标对象完成布局。void、未知类型和无法完成的按值布局不能查询；字节字符使用 u8，其大小/对齐均为 1。

空结构体大小 0、对齐 1；零长度数组大小 0、对齐取元素对齐。查询可以用于常量、普通表达式和数组长度；循环依赖必须诊断。未来表达式形式及跨平台大小类型仍另行讨论，TYPE-03 的其余事项未自动冻结。

### 7.6 分支选择

**用户已撤回 match 设计：**使用传统形状的 switch 语句，规则见第 8.3 节。switch 不产生表达式结果，不引入模式、守卫、Payload 解构或穷尽性机制。

## 8. 语句与控制流

### 8.1 条件与循环

**已确定的方向：**

```text
if (condition) { ... } else { ... }
while (condition) { ... }
do { ... } while (condition);
for (init; condition; step) { ... }
loop { ... }

break;
continue;
return value;
```

`...` 在本例中为内容占位，不代表可直接编译的语法。

**已确定（2026-11-16）：**`if`、`while`、`do...while` 和 `for` 中显式出现的条件必须为 `bool`，指针、数值和其他类型不因处于条件位置而隐式转换为真假。指针没有特殊例外，普通 bool 赋值、参数与返回位置同样不隐式接收指针。

以下示例假设 `p` 是指向 bool 的指针；空值写法沿用当前 `null` 方案：

```text
if (p != null) { ... } // 合法：显式检查地址是否非空
if (*p) { ... }        // 条件类型合法：判断目标 bool；调用方须先保证 p 可解引用
if (p) { ... }         // 编译错误：条件不是 bool
if (!p) { ... }        // 编译错误：逻辑 ! 不接受指针
```

**决定理由：**保留统一的显式规则，减少条件上下文的特殊转换，并区分“地址非空”与“目标值为真”。非空判断不承诺地址有效、对齐正确或对象仍存活。未采用此前讨论的指针条件简写方案。

**已确定（BD-19，2026-11-16）：**

- `if/else` 和循环均为语句，循环不产生值。
- 保留 `while`、`loop`、`do...while` 和 `for (init; condition; step)`；for 省略条件等价于 true。
- 所有控制体必须使用 `{}`，单语句体和空体均不例外；换行、缩进及下一条裸语句不决定代码体归属。`else if` 保留为链式分支语法，各分支体仍必须使用 `{}`，独立 else 后必须为块。
- 无标签 break 退出最近的循环；首版不支持带标签 break/continue。
- while/do...while 的 continue 转到条件检查；for 的 continue 先执行 step 再检查条件；loop 的 continue 回到循环开头。
- return 退出当前函数；作用域退出按第 8.2 节执行 defer 清理。

**待补齐：**完整无歧义 EBNF、for 初始化/迭代项的具体语法、不可达代码及返回路径分析。BD-22 的其余规则继续待审查。

**Stage 0 实现记录（2026-11-16）：**本节 BD-19 已实现，包含 bool 值、整数比较、指针相等/不等、逻辑短路、if/else、全部上述循环及 break/continue。当前 for 初始化至多一条声明/赋值/调用，迭代项至多一条赋值/调用，均可省略；初始化作用域覆盖条件、迭代项及体。未提供逗号项、复合赋值或 ++/--。局部块允许内层遮蔽、同层重复报错，暂按 BD-12 候选；这些详细边界不自动冻结为长期标准。

当前保守检查可达末尾路径必须有返回，允许无出口的无限循环；只利用直接常量 bool 判断不可达，不证明任意算术或循环终止。不可达源码仍检查名称/类型，显式 := 常量仍必须求值成功。编译期函数也可执行分支/循环/终止递归，有资源预算，尚不支持编译期指针。完整实现文法与限制见[基础编译原型](parser_subset_v0_1.md)。

### 8.2 `defer`

**已确认并实现（BD-20）：**`defer` 的延迟体可以是代码块或单个直接函数调用，均可附带括号包围的 bool 条件。直接调用以分号结束，调用结果丢弃。

```text
defer cleanup();
defer { cleanup(); }
defer (ready) cleanup();
defer (ready) { cleanup(); }
```

`defer` 在所属词法作用域退出时执行。同一作用域中已执行到的 defer 按登记的相反顺序执行。条件和延迟体在声明处解析名称，在轮到该条清理时读取这些绑定的当前值。条件求值一次，为真时才执行延迟体并求值实参。前一条已执行的清理可以改变后一条的条件或实参。

```text
n: i32 = 1;
defer {
    record(n);
}
n = 2;
// 作用域正常退出时 record 收到 2
```

正常结束、`return`、`break`、`continue` 和 `#through;` 只清理实际退出的作用域，由内到外执行。循环体每轮独立登记。`return` 先求得并保存外层函数的返回值，再执行清理。按值返回的结果保留求值时的内容，经返回指针读取的对象可观察到清理中的写入。延迟块内可以再写 `defer`，也可以跳转到块内的控制目标。禁止在延迟块内 `return` 或跳到块外的控制目标。

语言没有异常展开。进程终止、硬件故障、未定义行为和外部 `longjmp` 不保证执行清理。当前降低方式与资源限制见[实现子集](parser_subset_v0_1.md#延迟清理的当前实现)。

### 8.3 switch

`switch (expression) { case constant: statements ... default: statements ... }` 接收整数值，包括枚举成员及计算结果。选择表达式求值一次。`case` 表达式必须在编译期求得和选择值相同具体类型的整数，例如 `case 1 + 1:` 或 `case #run f():`。重复值在求值后报错。`default` 至多一个，可位于任意位置。无命中且无 `default` 时离开 switch。

```text
switch (color) {
    case Color::Red:
    case Color::Green:
        result = 1;
    case Color::Blue:
        result = 2;
        #through;
    default:
        result += 10;
}
```

每个分支有独立的局部作用域；case 体不强制 `{}`，可以在分支内自由使用 `{}` 引入嵌套词法作用域。连续空标签共用后续分支；非空分支默认结束 switch，只有位于分支末尾的 `#through;` 才无条件进入源码中的下一分支，不重新匹配选择值。末尾分支和嵌套块内部不能使用 #through。

break 退出最近的 switch 或循环，continue 跳过 switch 寻找最近循环；仅在 switch 内使用 continue 报错。此规则补充第 8.1 节的循环退出契约，不改变 if/循环等体必须为 `{}` 的规则。首版降低为顺序比较及 CFG 跳转，无隐含标签或运行期 case 求值，尚无跳转表；分派比较、局部存储和跳转仍有实际成本。不要求枚举穷尽覆盖，不用成员列表证明函数必然返回。

## 9. 聚合类型与枚举

### 9.1 结构体

**已确定的方向：**`struct` 的字段同时存在。

```text
struct Vec2 {
    x: f32;
    y: f32;
}
```

**已确定（2026-11-16，2026-11-17 补充）：**支持 `{.field = expression}` 指定字段初始化。字段允许声明默认值；省略字段时优先采用该默认值，其余字段按类型默认初始化。标量默认零值；嵌套结构体递归应用其字段默认值。空初始化器 `{}` 和省略变量初始化器采用同一默认初始化规则，显式指定的 0/null 可以覆盖非零默认值。

```text
struct Point {
    x: i32;
    y: i32;
}

value: i32 = 7;
p: Point = {.x = value};  // p.x 为 7，p.y 为 0
zero: Point;              // 两个字段均为 0
fixed: Point := {.y = 2}; // 常量聚合方向示意，x 为 0；当前原型尚未实现 := 结构体常量
```

```text
invalid: Point = {.z = 1}; // 编译错误：Point 中不存在字段 z
```

**已确定（2026-11-16）：**同一结构体初始化器中，同一字段不得重复指定，即使两次初始化值相同也为编译错误；不采用后一次覆盖前一次的规则。

```text
duplicate: Point = {.x = 1, .x = 1}; // 编译错误：字段 x 重复初始化
```

以上示例中初始化器的类型来自目标声明。当前也支持从参数和返回类型取得上下文，以及嵌套指定初始化。显式初始化项按源码顺序求值。当前字段默认值须是可在编译期求得的标量，可引用编译期常量并调用 VM 能执行的函数。读取运行期全局会报错，外部函数按第 12.2 节匹配宿主绑定。一般聚合常量、运行期字段默认值、无上下文的初始化器、位置初始化及一般构造表达式继续审查。

**已确定（BD-16，2026-11-16）：**首个 Windows x86-64 目标采用小端、自然对齐和声明顺序布局，各字段向上对齐，结构体对齐取字段最大对齐，总大小补齐到该对齐的倍数。不自动重排字段，首版不提供 packed、位域或自定义对齐。整数/浮点基本类型对齐为其 1/2/4/8 字节自然对齐，数据/函数指针对齐为 8。

空结构体大小为 **0 字节**、对齐为 **1 字节**。零长度数组大小为 0，对齐与元素相同；遵循自然布局计算后，仅包含零大小字段的结构体也可能大小为 0，其对齐仍由字段决定。以上零大小表示不默认声称兼容 C 结构体或其按值 ABI。

结构体和数组首版不提供自动 `==`，需要显式逐字段或库比较；不能以填充字节 memcmp 代替值比较。正大小普通 C 兼容成员的布局仍须与目标工具链及 ABI 对照，确认本条不等于完成完整 FFI 验收。

```text
struct Empty {}
marker: Empty;       // 有类型的零大小值，不需要为内容写入数据字节
// sizeof(Empty) 为 0，alignof(Empty) 为 1
```

**当前实现：**结构体为名义类型，同布局的不同声明不隐式互转。普通赋值、实参和返回形成值副本；内嵌结构体随内容复制，指针字段仍共享其目标。可变对象和显式解引用的字段可写，参数字段及临时对象字段不可赋值。字段读取可用于函数返回的临时结构体。

**待定：**其余构造语法、完整聚合/常量/生命周期模型、C 兼容布局的显式声明方式，以及零大小对象的地址身份、分配和最终调用约定。当前内部零大小按值调用可用，不声称与 C 兼容；含零大小成员的结构体也不开放 extern(C) 按值接口。零大小布局不自动确定其地址唯一性或原始指针算术规则，配套候选见审查稿 BD-16。

**已确定（MEM-03）：**`.` 统一负责结构体对象的字段定位；无论对象来自普通变量还是显式解引用，规则相同。指针本身不能直接用点号访问目标字段，必须写 `(*p).field`。此前允许点号直接接收一层指针的候选已撤回。例子与理由见审查稿 BD-13 的“结构体字段定位与显式解引用”。

### 9.2 无标签联合体

**已确认并实现：**`union` 为无标签的名义类型，采用目标 C 的自然布局；所有成员偏移为 0，对齐取最大成员对齐，大小取最大成员大小后补齐到该对齐。不自动记录当前有效成员，不生成有效成员检查。首次支持范围为当前已实现的整数、bool、数据指针、结构体、union 和固定数组成员。

```text
union RawValue {
    bits: u32;
    signed_value: i32;
    bytes: [4]u8;
}
value: RawValue = {.bits = 0x12345678};
value.bytes[0] = 0;
```

- 使用现有 `.member`、`(*p).member`、取地址及数组索引访问共享存储；整体赋值、传参和返回复制整个 union 值，指针成员仅复制地址。没有自动相等/排序比较。
- 省略初始化器或使用 `{}` 时清零整个 union 存储，不逐个初始化重叠成员，也不应用这些成员类型内部的结构体字段默认值。指定初始化器形如 `{.member = expression}`，至多指定一个成员；明确选择结构体/数组成员后，其内部沿用自身初始化规则。成员声明不提供 `= expression` 默认值。
- 允许写入一个成员后通过另一个成员读取同一存储的目标对象表示；这不执行数值转换。读取的表示必须对目标成员类型合法，并满足对象大小、对齐、访问权限和寿命要求。非法 bool 表示、无效指针或陷阱表示不因来自 union 而合法；全零存储也不意味着每种未来成员类型都可任意读取。
- 遵循 C 的表示边界：填充字节和写入较小成员后未覆盖的字节不能被假定为确定的新值；不得用它们构造可移植结果。C 的跨成员读取说明见 [WG14 DR 257](https://www.open-std.org/jtc1/sc22/wg14/www/docs/dr_257.htm)。这次实现不额外冻结一般原始指针的完整来源/有效类型/别名模型。
- 支持普通 union 全局及结构体/union 内嵌 union 的简单静态初始化，沿用第 11.2.1 节的标量编译期求值和 null 指针边界。当前 Windows x64 的 C 按值调用采用与结构体相同的大小分类，目标依据见 [Microsoft x64 调用约定](https://learn.microsoft.com/en-us/cpp/build/x64-calling-convention?view=msvc-170)；不据此承诺其他目标 ABI 或浮点成员已支持。

首版不支持匿名 union/匿名成员、位域、空 union 定义、packed/自定义对齐或聚合编译期值；`union Name;` 与已有 opaque struct 一样只声明指针目标，不支持之后补全。普通成员名与类型仍需显式书写。准确原型限制及验证范围见[实现子集](parser_subset_v0_1.md#无标签-union-的当前实现)。零初始化、按值复制仍有实际成本；无标签只表示不增加隐含标签和分派。

### 9.3 普通枚举

**已确认并实现：**枚举是带命名空间的整数常量集合，枚举名在类型位置是所选底层整数的别名，不引入独立的枚举值类型或运行期标签。

```text
Color :: enum(u8) {
    Red,
    Green,
    Blue,
}
```

省略 `(Type)` 时固定使用 i32，与操作系统无关。普通枚举首个未显式赋值成员为 0，后续为前一个成员值加 1；可用 `Name = constant` 指定值。成员名或值重复、字面量超范围及自动递增溢出均报错。成员写作 `Color::Red`，导出枚举可直接/命名导入，跨命名模块写作 `module::Color::Red`。

`Flags :: enum(bit8) { Read, Write, Execute, }` 使用 u8 存储，自动值为 1、2、4；bit16/32/64 对应 u16/32/64。显式位成员必须是非零单一位，自动左移越过位宽报错；不允许声明 0 或复合掩码成员。这只限制成员定义，普通变量默认值和运算结果可以为 0，也可以是多个位的组合。

成员与该底层整数完全相同，可以任意整数计算、比较、位运算、赋值、传参/返回、用作数组长度及索引。例如 `1 + Color::Red` 按 u8 计算，`data[Color::Red]` 无需 cast，`data: [Color::Count]u8;` 可直接使用计数成员。不同枚举若底层类型相同也可直接混算；已有的具体整数类型之间不隐式转换，有符号/无符号或位宽不同仍需显式 cast。枚举名可用于绑定、字段、数组、指针和 cast/sizeof/alignof；IR 和 C ABI 均使用实际整数类型，不跟踪运行期值是否对应某个成员。

枚举定义本身只产生编译器名称/值元数据；使用成员不需要运行期查表、装箱或成员有效性检查，普通整数运算/存储的成本仍存在。当前显式成员初值采用布局常量表达式子集，依赖、资源及模块边界见[实现子集](parser_subset_v0_1.md#枚举与-switch-的当前实现)。此规则取代 BD-17 中独立枚举值域、必须声明零变体和非法非成员值的候选。

### 9.4 携带数据的枚举

**长期目标，尚未实现：**由编译器维护标签和当前有效变体的判别联合体仍独立讨论。本次整数枚举不实现 Payload；撤回 match 后，其访问/分派语法需重新设计，不能沿用已撤回的模式解构规则。

```text
Expr :: enum {
    Integer(i64),
    Float(f64),
    Binary(*BinaryExpr),
}
```

**待定：**变体构造与解构、Payload 数量和命名、移动/复制、标签表示和内存布局。

**建议：**不默认承诺携带数据枚举符合 C ABI；需要 C 互操作时显式使用 C 兼容表示。

## 10. 值、存储与内存行为

语言面向底层编程，但目前尚未确定完整内存模型。以下问题必须在相关功能进入冻结子集前解决：

| 主题 | 待确定的规则 |
| --- | --- |
| 值与复制 | 标量、数组、结构体、联合体、枚举的赋值与参数/返回值语义 |
| 初始化 | 已确定标量默认零值、结构体省略字段优先采用声明默认值及编译期常量显式求值；继续确定各类型零值、动态原始内存及填充字节边界 |
| 生命周期 | 局部、全局与动态对象的存储期，悬垂指针 |
| 可变性 | 绑定、对象、字段、指针的可写性 |
| 指针 | 空值、算术、比较、整数转换、单独形成越界地址是否合法 |
| 访问有效性 | 越界、错位、空指针、失效地址以及非法枚举/联合体访问 |

**建议：**初期通过 C ABI 使用现有分配器，采用显式释放，不强制 GC；具体分配接口属于基础库契约。

**待定：**对每类非法行为区分静态错误、必须检查的运行时错误、显式允许的低层行为和未定义行为。尚未定义不表示已经选择“未定义行为”。

原子操作、`volatile` 和并发内存模型不在当前首版实现范围中；后续若加入，需要单独定义。

## 11. 模块与名称空间

本节区分已确认的导入规则与仍待审查的模块边界。用户已确认直接导入及命名模块绑定两种形式、同一模块只加载一次、导入符号重名报错，以及私有名称仍在定义模块中解析。此前默认文件名绑定与可选 `as` 的方案已由下述形式取代。当前 Stage 0 已实现相对 .ar 导入、函数及已支持全局变量的导出。准确能力与限制见[实现子集](parser_subset_v0_1.md#模块与全局的当前实现)。

### 11.1 导入、别名与限定访问

`import` 解析目标模块；直接导入与命名模块绑定决定其公开声明在导入方的访问方式。模块文件的定位与导入方名称绑定分别处理。

```text
// 直接引入 math 的公开名称，不绑定默认模块名
import "math";

fn main() -> i32 {
    return add(1, 2);
}
```

```text
// 命名模块绑定：只引入名称 m
m :: import "math";

fn main() -> i32 {
    return m::add(1, 2);
}
```

**已确认（MOD-01）：**

- `import "path";` 将目标模块的公开声明引入当前模块作用域，直接以声明名称访问；不按文件名自动创建模块绑定。
- `name :: import "path";` 只创建名为 name 的模块绑定，通过 `name::member` 访问公开声明，不同时引入裸成员名。
- 两种形式均以分号结束，可以同时用于同一个目标模块；它们引用同一模块中的声明，不产生新的模块实例。
- 导入引入的名称在同一作用域内重名，或与当前模块的顶层声明重名，编译报错；不按导入顺序覆盖，也不自动合并重名函数。重复引入同名绑定同样报错。
- 模块限定访问使用 `::`，对象字段使用 `.`；`name :: import` 是模块绑定声明，不将 `::` 扩展为普通常量声明。

**当前范围方案：**导入位于模块顶层；局部导入、选择性导入、显式通配语法及再导出暂不纳入。直接导入公开名称不自动将其再导出。局部名称遮蔽继续单独审查。

命名模块绑定只影响导入方如何找到声明，不修改定义模块的名字，也不改变其内部名称解析环境。`import` 为关键字，可据此区分模块绑定声明与普通限定访问，空格不改变 `::` 的含义。

### 11.2 公开声明

`export` 控制语言模块的公开接口。

```text
// math 模块
export fn add(a: i32, b: i32) -> i32 {
    return helper(a + b);
}

fn helper(value: i32) -> i32 {
    return value;
}
```

**当前方案：**顶层声明默认模块私有；显式 `export` 的声明可由直接导入或模块限定访问使用。上例的 `add` 可从其他模块访问，`helper` 保持模块私有。

**已确认：**导出函数体中的模块级名称依赖在定义模块中解析，并遵守函数自身的词法作用域。上例中 add 调用的是 math 的私有 helper，导入方即使有同名 helper 也不改变调用目标。私有声明不会随直接导入变为公开，也不能借助限定访问绕过可见性。

语言模块的 `export` 不自动表示生成供 C 或其他外部程序使用的链接导出符号；后者由独立的 FFI/目标契约规定。

**待定：**可导出的声明种类、公开函数或类型引用私有类型时的规则、结构体字段可见性和未来再导出机制。

#### 11.2.1 导出全局变量的存储

**已确认：**普通模块全局变量的每个定义在同一程序、同一模块身份下对应一个共享的存储对象，存储期持续到程序结束。`export` 只改变可见性，不改变存储归属；私有全局变量也属于定义模块。直接导入、不同模块别名及不同导入方均访问定义模块中的同一对象，不为每条 import 复制变量或重新初始化。

```text
// state.ar
export counter: i32 = 0;
```

```text
// 使用方
import "state";
state :: import "state";

fn main() -> i32 {
    counter = 7;
    snapshot: i32 = state::counter;
    state::counter = 9;
    return counter - snapshot; // 预期返回值为 2
}
```

- 导出的普通变量沿用普通变量的可变性，允许导入方读取和赋值；任一访问方式修改原对象后，其他访问方式读取同一对象的当前值。
- 导入绑定共享原对象；`snapshot: i32 = state::counter;` 则复制当时的 i32 值，不成为该对象的别名。指针或聚合值的复制继续遵循相应类型规则。
- `export limit: i32 := 10;` 若纳入可导出声明，仍是不可赋值的编译期常量，不据此要求为它保留独立的运行期存储或地址。
- 该设计不需要每次导入的对象分配、值复制、运行期名称查找、引用计数或锁；普通全局读写仍有必要的访存成本，外部可写别名也会限制部分常量传播和访存消除。
- 共享不隐含原子访问、自动同步或跨进程共享内存。并发内存模型、动态库/多模块实例及跨二进制唯一性仍需分别设计，不纳入当前承诺。

**已确认并实现的增量：**普通结构体全局支持默认初始化和花括号指定字段的静态初始化。省略字段优先采用声明默认值，其余按类型默认初始化；嵌套结构体和字段数组递归采用同一规则。初始化器的标量叶子必须可编译期求值，字段指针初值当前限 null。

普通固定数组也可在模块顶层声明和导出。`mat: [2][3]i32 = {{1, 2}, {3}};` 使用逐层花括号列表，省略的元素按类型默认初始化。全局数组复用静态聚合初始化规则，标量叶子须可编译期求值，指针初值限 null。

```text
struct State {
    count: i32;
    ready: bool = true;
}
state: State;
export configured: State = {.count = 3};
```

这些定义直接生成静态对象，运行期可修改字段或整体复制；不生成隐式运行期初始化调度。当前不支持 := 聚合常量、从聚合对象/聚合返回调用生成初值和非零地址重定位，准确边界见[实现子集](parser_subset_v0_1.md#结构体的当前实现)。这不决定完整动态初始化的合法性和顺序，BD-24 的长期规则仍单独审查。

### 11.3 相对模块路径

**当前首版方案：**导入字符串相对于包含该 `import` 的源文件所在目录解析，并补上统一的源文件扩展名。首版示例省略扩展名，正式扩展名仍待决定。

```text
模块候选文件 = 导入方源文件目录 / 导入字符串 + 源文件扩展名
```

以下目录中的 `.my` 仅为扩展名占位示意，不是已确定的语言扩展名：

```text
project/
├── src/
│   ├── main.my
│   └── math.my
└── common/
    └── utils.my
```

`src/main.my` 中的导入示例：

```text
import "math";                     // project/src/math.my，直接引入公开名称
import "../common/utils";          // project/common/utils.my，直接引入公开名称
tools :: import "../common/utils"; // 同一个模块，另行绑定 tools
```

- 路径基准始终为导入方源文件目录，编译器进程的工作目录不参与该相对路径的含义。
- 导入字符串中的 `/` 用作目录分隔符，允许通过 `.`、`..` 表达相对路径。
- 文件不存在时给出编译错误，诊断显示导入位置与实际尝试的完整路径。
- 当前方案仅定义相对源文件导入；绝对路径、显式扩展名、目录入口文件、标准库前缀、包名和额外搜索目录的规则尚未确定。
- 将来若支持标准库或第三方包，应显式扩展解析规则，不能让当前已合法的相对导入悄然绑定到其他模块。

### 11.4 模块身份与依赖

**已确认：**`import` 是模块解析和名称绑定，不进行源码文本粘贴。一次编译中，同一模块身份只加载并解析一次；不同路径拼写是否为同一身份按模块身份规则判断。直接导入和不同命名绑定不改变模块身份，重名诊断见第 11.1 节；目标模块的私有名称依赖仍在定义模块中解析。

**其余建议：**

- 模块先提供顶层声明，再按需解析与检查内容，保持顶层声明顺序无关。
- 循环导入不必一律禁止，但不可解的编译期依赖循环必须诊断。
- 编译期生成的新导入和受影响声明继续参与模块处理；AST 变更可以触发重新分析。

**待定：**Windows 路径大小写、路径规范化、符号链接/文件别名如何影响模块身份，局部名称遮蔽，循环模块初始化及编译期生成导入的路径基准。首个实现应在相关代码落地前明确这些边界。

已确认规则的验证预期（对应回归入口见 tests/README.md）：

| 场景 | 预期 |
| --- | --- |
| 同一模块被直接导入，并另行绑定为 m | 只加载一次，两种访问方式指向相同声明 |
| 两个直接导入引入同名公开声明 | 编译错误，不按顺序覆盖 |
| 导入名称与本模块顶层声明重名 | 编译错误 |
| 命名模块绑定重复同名 | 编译错误 |
| 导入方访问未 export 的 helper | 编译错误，直接和限定访问均不可绕过 |
| 导出的 add 调用私有 helper，导入方也有同名 helper | 继续调用定义模块中的 helper |

## 12. 编译期执行与 AST 元编程

### 12.1 能力边界

| 写法 | 含义 |
| --- | --- |
| `#run f(args)` | 在编译期执行直接函数调用，可使用模块限定名。表达式位置取得返回值，独立语句可丢弃结果或调用 void 函数。 |
| `#run { statements }` | 独立执行无结果块，可在函数内或模块顶层使用。 |
| `#run -> Type { statements }` | 块表达式。每条正常结束的路径必须以 `return expression;` 给出声明的结果类型。 |
| `#insert #run f(literals)` | 在解析当前位置前执行生成器，按第 12.6 节替换源码字节。 |

普通 `#run` 在声明完成插件投递、被调函数具备类型与字节码后求值。调用的实参可包含编译期已知的表达式，块可读取外层 `:=` 常量。读取所在运行期函数的形参或可变量会报错。VM 只执行选中分支，失败直接产生编译错误。一般常量表达式可用 `:=` 或 `case`。模块/函数内的 `a: i32 = #run square(3);` 创建可变量，`b: i32 := #run square(3);` 创建常量。

### 12.2 值与宿主能力

整数位宽、环绕、比较、目标布局与运行期语义一致。Stage 0 支持将整数、bool 和函数体内使用的零结尾 `*u8` 字节串物化为运行期数据。空指针可以表示为目标 null。任意 VM 内存地址、文件句柄和聚合编译期结果的通用物化另行定义；全局指针静态初始化的当前限制见[实现子集](parser_subset_v0_1.md)。

编译期可通过已绑定的宿主 C 函数执行文件 I/O 和内存操作。宿主是执行编译器的机器，函数签名必须匹配。执行到未绑定的函数时报错。两次显式的生成器调用各自读取当时的输入。[当前宿主绑定](../src/vm_memory.c)

### 12.3 声明事件与注解

- 编译参数依次指定插件。`.ar` 插件先编译，其他语言可以实现相同的固定回调 ABI。编译用户模块前，可选注册入口声明注解名及该注解启用的中缀运算符。重复注册同名注解报错。
- `@name` 是当前顶层声明的元数据，可用于函数、类型、全局、导入及顶层编译期语句。未注册的名字原样保留。只有已注册的能力改变该声明的解析。符号、优先级和结合性在注册时提供，使用处只写注解名。同一声明激活冲突的符号定义时报错。
- 顶层声明解析成语法树即投递，按插件参数顺序逐个消费。同一声明对每个监听器只投递一次。修改后检查语法结构，将当前版本传给下一位；类型检查在消息循环结束后进行。此时未改写为语言可定型形式的自定义运算符报错。
- 插件可通过句柄修改节点，或以 `#keyword(handle)` 获取**当前版本**的规范化源码，编辑后交回编译器重解析。表达式替换保留分组。声明 ID 贯穿此次投递，表达式句柄只在当前回调和当前 AST 版本内有效。原文另存用于诊断。
- 回调可替换当前声明，或向所在模块追加新的顶层声明。每个新声明从第一个监听器开始。重名及无法解析的最终引用按普通语言规则诊断。[接口与示例](../docs/metaprograms.md)

### 12.4 依赖与求值次数

普通声明可引用稍后出现或注入的定义。例如 `main` 先完成监听器回调，也要等最终声明集合足以解析调用后才生成字节码。`#insert` 有更早的时间约束，生成器和辅助定义在插入点就必须可用。生成器本身已经经过自己的声明事件。

在同一次 clean build 中，一个词法求值请求完成后可供依赖它的位置复用。每个显式插入点都调用生成器，函数指令可以复用。依赖通过保存的执行状态挂起和恢复；编译期依赖环、展开资源耗尽及 VM 求值失败均报错。没有依赖关系的独立副作用之间，语言暂未规定跨模块的全序。

### 12.5 观察与诊断

`--emit-ast` 展示展开和监听器修改后的语法树。`--emit-ir-before-opt` 展示普通 `#run` 已回填的带类型寄存器字节码。生成文本中的错误指向相应片段，并回溯插入或替换点；VM 错误可附编译期调用位置。完整求值日志、生成版本浏览及其命令行形式待定。[诊断与示例](../docs/diagnostics.md)

### 12.6 源码插入

`#insert #run f(args)` 取编译期调用返回的源码文本，在指令所在位置展开。生成文本和周围源码一起按 ATRI 语法解析，运算符优先级作用于展开后的整段代码。

用于源码插入的生成函数必须在展开点之前已有完整定义。每个实参在该位置都必须有编译期已知的字面量值。生成函数可使用编译期内建能力，也可调用宿主 C 库执行 I/O。例如，`#insert #run emit_protocol("protocol.json")` 在本次构建中读取协议文件，将生成的声明插入当前位置。

若生成器尚未定义，或调用需要读取所在函数的运行期形参或局部变量，则在插入点报错。生成函数可以返回含有这些名字的文本，例如 `n + 1`。展开后，编译器按插入位置的作用域解析 `n`。

例如，若 `make_expr()` 返回文本 `1 + 2`，则 `return 2 * #insert #run make_expr();` 展开为 `return 2 * 1 + 2;`，结果为 `4`。调用者可以写 `return 2 * (#insert #run make_expr());` 显式分组，结果为 `6`。

替换范围从 `#insert` 开始，到 `#run` 调用配对的右括号为止。后面的分号属于周围源码。生成器也可以自己提供分号，例如 `emit()` 返回 `1 + 1;` 时，`return #insert #run emit()` 展开为 `return 1 + 1;`。编译器从插入位置继续扫描，遇到新的有效 `#insert` 就递归展开；生成的字符串字面量和注释中的同名文本遵循通常的词法规则。

以完整顶层声明为 AST 事件的投递单位时，影响声明语法结构的插入点须先完成展开，才能投递该声明。由展开生成的顶层声明也按相同流程处理。Stage 0 使用零结尾的 *u8 返回源码，按调用者作用域解析插入结果。生成器只能通过字面量输入、已定义的辅助函数、类型与宿主能力计算正文。

### 12.7 仅编译期使用的符号

**已确认的产物要求。** 在所有优化级别（包括 O0），仅供编译期执行的函数及其专用数据都从目标可执行文件中排除。例如，若 `emit` 只由 `#insert #run emit()` 调用，最终程序中不应有 `emit` 的函数体、链接符号或仅供它使用的宿主库导入。若它生成的函数被 `main` 调用，该函数按普通运行期代码输出。

同时被 `#run` 和运行期代码调用的函数按各自用途处理：编译期调用交给 VM，运行期调用保留所需实现。编译期求出的值若被运行期代码使用，可以成为立即数或目标数据。验收时应同时检查机器码、符号、专用数据和外部导入；只移除符号名不足以证明函数体已排除。

## 13. C 互操作与执行环境

### 13.1 外部函数

**已确认（2026-11-16，ABI-01）：**稳定 ABI 目标与目标平台 C ABI 保持一致；普通函数当前也采用 Windows x64 C 调用机制，本轮不另设内部调用约定。完整 C ABI 兼容仍按类型和功能逐步验收。外部函数使用属性声明：

```text
#extern(C) fn puts(text: *u8) -> i32;
```

`extern(C)` 指定外部 C 函数，链接符号使用源码函数名，不添加内部函数编号。当前只接受完整、固定参数签名和以分号结束的声明；未知属性/调用约定、外部函数体和重复函数名均报错。该属性不自动加载 DLL 或解析 C 头文件；链接依赖由外部工具显式提供。

字符指针的 C 原型映射按下表执行。这里的“映射”同时记录 ABI 表示和接口权限；表示相同不等于全部 C 类型限定均已在 ATRI 类型系统中表达。

| C 原型中的类型 | 当前 ATRI 声明 / 边界 |
| --- | --- |
| `char *` 参数或返回 | `*u8`，按同一个目标地址传递；可写性、长度、寿命与所有权依实际接口契约，不由该拼写单独保证 |
| `const char *` 参数或返回 | ABI 层暂以 `*u8` 对接；必须遵守 C 接口的只读访问权限，不声称具有完整的目标只读类型检查 |
| `unsigned char *` / `uint8_t *` | *u8，访问无符号字节 |
| `signed char *` / `int8_t *` | *i8，访问有符号字节；与 *u8 之间需要显式数据指针 cast |
| `wchar_t *`、`char16_t *`、`char32_t *` | 当前未实现对应目标类型；不得用 `*u8` 假冒宽字符缓冲区或期待隐式转码 |
| `void *` | *void，薄数据指针；必须显式转换为完整对象指针后访问，不能直接解引用或算术 |
| `const void *` | ABI 层以 *void 对接，但仍须遵守只读访问契约；没有完整的目标限定类型检查 |
| `FILE *` | 示例用 `struct FILE;` 声明 opaque 类型，以 *FILE 传递运行库拥有的句柄，不伪造 FILE 的内部布局 |
| `char **`、函数指针及其他尚未支持的指针 | 继续按各自类型与 ABI 设计，不因数据指针表示相同而自动获得这些类型能力 |

C 的 `const char *` 与 `char *` 在当前目标上具有相同的指针传递表示，但 const 所表达的访问权限必须继续遵守。const 限定经该指针的写入权限，不保证同一可写对象不会经其他别名变化，也不证明被调函数纯净或不会修改其他内存。字面量可以传给已知只读的 puts；将其传给会改写输入的 C 接口仍是非法访问。未来目标只读类型的语法继续单独审查，不恢复已撤回的运行期 const 绑定，也不把当前的权限缺口描述为已经完成的完整 C 类型兼容。

`puts` 的 C 原型为 `int puts(const char *)`，当前声明对应其中的指针表示和目标 32 位 int 返回值。puts 的第一个也是唯一的显式参数按 Windows x64 约定放入 RCX，传入的是字符数据地址，不是“指针变量的地址”，也不附加长度或容器描述；一般函数仍按实参序号分配寄存器/栈位置。指针返回值使用 RAX，puts 的 i32 返回值使用 EAX。调用仍须满足目标寄存器保存、32 字节 shadow space 和栈对齐要求，具体契约由后端按 [Microsoft x64 调用约定](https://learn.microsoft.com/en-us/cpp/build/x64-calling-convention?view=msvc-170)实现。

puts 读取到第一个零字节，向 stdout 输出此前的字节并附加换行；终止零不作为输出内容，也不被改写。输入必须为有效零结尾字符串，不能用 null 表示空串；成功返回非负数，失败返回负值，不能把返回值当成已打印字节数。换行的外部字节形式及终端显示仍受 CRT 流模式和终端编码影响。依据见 [Microsoft puts](https://learn.microsoft.com/en-us/cpp/c-runtime-library/reference/puts-putws?view=msvc-170)。

声明必须与实际 C 原型的目标类型、参数数量和调用约定匹配；编译器当前无法读取 C 头文件核对声明，也不自动证明外部代码遵守权限和生命周期契约。字符表示、终止零、字面量及所有权规则统一见第 5.5 节。

C ABI 兼容不表示编译器必须解析 C 源码或 C 头文件。

### 13.2 首次实现的边界

**当前实现：**固定参数的八种定宽整数、bool、已有数据指针和 void 返回，以及外部调用，整数与指针分别对接对应目标 C 表示，bool 对接 `_Bool`；bool 不等同于 Win32 的 32 位 `BOOL`。支持 `puts` 真实标准输出。编译期可用的宿主绑定见第 12.2 节。

当前已覆盖正大小普通结构体的 C 布局与按值 ABI，包括小对象寄存器传递、大对象间接参数与隐藏返回缓冲区。浮点、可变参数定义端/va_list、其余聚合 ABI、回调/函数指针及正式导出语法尚未实现；首轮通过不代表完整兼容。普通非 main 定义的 `atri_fn_<索引>` 仍是后端临时符号，不属于已承诺的稳定公开接口。

具体的寄存器、栈布局、shadow space、聚合传递和栈展开等属于目标 ABI 实现契约。语言规范负责说明哪些声明允许跨边界，以及这些声明具有什么类型和行为。

**待定：**完整 C 类型映射、C 兼容聚合布局、函数指针兼容性、浮点可变参数与定义端、正式导出/跨模块符号规则和扩展程序入口。稳定 ABI 与 C 一致不改变语言自身的按值语义和已确认布局规则；不兼容 C 的类型必须另行确定跨边界表示。

初期错误处理建议使用普通返回值或错误码；不要求先实现专门的 Result 语法。语言不提供异常机制已确定。

### 13.3 C 可变参数、void 与 opaque 类型的当前子集

按本轮 C ABI 要求，支持 `#extern(C) fn printf(format: *u8, ...) -> i32;`。ellipsis 只能位于参数表末尾；当前也接受 C23 的纯 `...` 声明。普通 ATRI 函数定义暂不接受 ellipsis，不提供 va_list/va_arg。调用至少提供全部固定参数，固定参数继续精确类型检查；尾部按各实参定型并按源码顺序求值。

尾部 i8/u8/i16/u16/bool 按目标 C 默认参数提升变为 i32，i32/u32/i64/u64 与数据指针保持对应表示，C 兼容普通结构体沿用已有按值 ABI。这个提升是 C 调用边界规则，不开放普通 bool 整数转换或隐式整数赋值。强类型数组不退化，须显式传元素指针；无上下文的 null 须写作 `cast(*T, null)`。格式字符串、va_arg 类型、数量及有效访问必须由调用方与 C 接口匹配，编译器当前不做 printf 格式验证。

Windows x64 沿用四个整数参数寄存器、shadow space、栈参数及聚合的副本/隐藏返回缓冲区规则，不生成语言级变参容器。浮点仍暂缓，当前不能把整数位模式当作 double 可变参数；以后实现浮点时必须同时补齐默认提升及 x64 的浮点/整数寄存器双写。依据：[C23 工作草案 N3096](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n3096.pdf)的默认参数提升，以及 [Microsoft x64 varargs](https://learn.microsoft.com/en-us/cpp/build/x64-calling-convention?view=msvc-170#varargs)。本轮验证仅覆盖已支持类型，不等于完整 C ABI 验收。

void 可作为普通/外部函数返回类型，不是可存储的对象类型。void 函数使用 `return;` 或正常到达末尾；不接受带值 return，非 void 函数不能用裸 return。void 调用只能作为无值语句使用；sizeof(void)、void 字段/参数/变量与 void 元素数组均拒绝。Hosted main 仍须返回 i32，以对接当前 C 启动代码。

当前 `struct FILE;` 表示名义 opaque 类型：可以声明/复制/比较/传参/返回其指针，不能构造其值、查询对象布局或访问字段。它与 `struct Empty {}` 的零大小完整类型不同；当前不支持用随后同名定义补全，不能把此子集当作完整 C 类型前向声明系统。完整类型互操作语法可另行审查。

### 13.4 标准库文件读取示例

[例子绑定](../examples/c_stdio.ar) 显式声明 fopen/fread/fwrite/fclose/ferror/feof，使用 *FILE、*void 与当前目标的 u64 size_t。FILE 由同一 C 运行库创建和关闭，缓冲区容量、指针权限、有效寿命和错误返回均由用户显式处理；fread 不自动添加 NUL。[read_file.ar](../examples/read_file.ar) 使用文本模式并分块打印源码；二进制模式及 NUL/高位字节回归见测试说明。文件内容的字节读取不表示 filename 自动采用 UTF-8；Windows narrow fopen 仍依目标 CRT 的路径编码，宽路径接口尚未实现。

原型和行为依据：[Microsoft fopen](https://learn.microsoft.com/en-us/cpp/c-runtime-library/reference/fopen-wfopen?view=msvc-170)、[Microsoft fread](https://learn.microsoft.com/en-us/cpp/c-runtime-library/reference/fread?view=msvc-170)。CRT 的缓冲、锁、分配和 I/O 均有成本；显式调用 C 库不引入额外语言 GC/异常运行时，也不表示这些库操作免费。

## 附录 A. 核心可自举子集候选（新增讨论建议，非规范性）

本附录用于开始讨论，不是原草案已经确认的范围变更。完整语言目标继续保留；是否调整原 M2 先于 M4 的验收依赖，需要明确决定。

### A.1 范围判断方法

以“能够编写和构建编译器自身”为依据，先列出编译器实际需要表达的对象和操作：

- 源码字节、Token、源码位置和错误信息。
- AST、符号、类型、IR 指令及控制流图。
- 动态数组、字符串缓冲、映射及内存分配。
- 多文件源码组织、文件读取、汇编输出和进程退出。

这些需求可以有多种语言表达方式。自举不必先实现全部语法糖，但不能把缺少的表达能力转移成隐含且未规定的特殊行为。

### A.2 建议的首轮范围

| 范围 | 建议纳入的能力 | 原因或取舍 |
| --- | --- | --- |
| 基础计算 | `bool`、固定宽度整数、字面量、显式转换；`usize/isize` 是否纳入见 TYPE-03 | 词法、索引、大小和地址相关计算 |
| 函数与存储 | 函数、递归、局部绑定、所需全局存储、显式返回 | 表达编译器算法；初始化规则需先确定 |
| 数据结构 | 指针、结构体、定长数组、字段访问、索引 | 表达 AST、符号表、IR 和缓冲区 |
| 控制流 | `if/else`、`while` 或 `loop`、`break/continue` | 足以表达首轮算法，具体保留哪种循环待讨论 |
| 工程组织 | 模块导入和明确的名称解析 | 支持可维护的多文件编译器 |
| 执行环境 | 自举所需 C ABI、分配/释放、文件 I/O、输出、退出 | 可通过固定签名的 C 封装缩小首轮 ABI 范围 |
| 编译期基础 | 按需纳入最小 `#run`、常量/类型查询 | 是否为首次自举必备，取决于编译器源码是否使用 |

固定签名 C 封装是一种候选基础库方案，若采用，应明确它属于保留的外部依赖。

### A.3 需要选择的取舍

| 能力 | 首次自举中的价值 | 可选路径 |
| --- | --- | --- |
| 普通枚举 | 表达 Token 与节点类别 | 尽早支持，或临时使用具名整数常量 |
| Payload 枚举（访问/分派语法待重审） | 简化 AST/IR 的表达和分派 | 直接纳入，或先采用标签与结构体/联合体 |
| `union` | 紧凑表示变体数据和底层互操作 | 按真实布局需求纳入；不能仅因保留了语法就认为自举必需 |
| `defer` | 简化资源清理和错误路径 | 尽早支持，或先显式清理 |
| 函数指针 | 回调、可替换策略与 ABI 互操作 | 取决于首版编译器和 C 接口是否需要 |
| `f32/f64` | 编译用户语言中的浮点程序 | 编译器可用整数表示浮点位模式；完整支持时机待定 |
| 完整 `#run` 与任意 AST 修改 | 实现语言的重要长期能力 | 可按原路线在首次自举前完成，或先完成独立的基础自举 |

“实现编译期解释器”和“编译器自身使用编译期元编程”是两件事。前者可以用普通运行期代码实现；后者会增加 Stage 0 必须支持的能力。

是否将完整 Comptime 验收与首次自举拆开，是 CORE-01 的核心问题，本文不代为决定。

每轮讨论应区分“用户已明确接受的规则”和“仍在评估的建议”；只有前者进入已确定规则。实现不能依靠未记录的临时语义填补空缺。
