# IR 验证、优化与 Windows x64 生成

## 一个值在汇合点能否使用

假设 `if` 的真分支产生值 `v`，假分支直接跳到汇合块。如果汇合处直接使用 `v`，走假分支时就没有定义。即使 `v` 的指令在文件中排在使用点之前，验证器仍要拒绝它。合法的跨分支可变状态可以用一个在分支前创建的局部对象承载，两边写入，汇合后读取。

验证器先检查块标签、终结指令和跳转目标，再从入口传播可达性。已知布尔常量的条件只沿选中的边传播。若可达路径落到非 void 函数末尾的 `UNREACHABLE`，就报告缺少返回值。[验证器中的 verify_function](../src/ir_verify.c)

随后计算**支配集合**。若到达块 B 的每条入口路径都经过块 A，就称 A 支配 B。入口的集合只有自身。其他可达块反复取所有可达前驱集合的**交集**，再加入自身，直到集合不变。取交集正好排除了只在某个分支出现的定义。验证器用位集保存这些集合，并逐条核对操作数的定义顺序、支配关系、类型和调用签名。[非法 IR 测试](../tests/verifier_tests.c)

## O0、O1 和 O2

默认 O0 对直线字节码做局部折叠和死指令消除，随后直接选择 x64 指令。O1 将字节码翻译成 LLVM IR，由 ATRI 遍历函数、基本块和指令，按整数位宽折叠常量，并以原操作数替换 `x + 0` 等恒等式的所有使用，删除旧指令，再用 LLVM 验证模块。O2 使用同一翻译入口，交给 LLVM 的标准优化管线。两档都由 LLVM 生成目标码，Windows 汇编及链接由驱动调用本机 Clang 工具链完成。[O1 实现](../src/llvm_pass.c) · [LLVM 翻译器](../src/backend_llvm.c) · [工具驱动](../src/clang_driver.c)

## 字节码上的局部优化

优化器只改写满足条件的直线函数，多块函数、含跳转或聚合访问的函数保留原有控制流与存储。直线代码按定义顺序重建，旧指令 ID 映射到新 ID，调用实参也要同步重映射。[优化器](../src/optimize.c)

| 步骤 | 算法和边界 |
| --- | --- |
| 常量折叠 | 当算术指令的输入都是常量，以目标整数位宽计算并替换结果。例如 `u8` 的 255 加 1 得到 0。解释器和优化器共用位模式运算，`-O0` 也可折叠。 |
| 叶函数内联（独立字节码优化器测试） | 对符合大小和指令限制的被调函数，把形参映射到调用者实参，复制函数体，用返回的值 ID 替换调用结果。代入常量可触发新的折叠。逐轮处理可继续内联新形成的叶函数。 |
| 死指令消除 | 从返回、写存储和保留的调用向前追溯操作数。直线代码的定义总在使用之前，逆序扫描一次即可标记依赖。调用即使没有接收结果，也可能写内存或永不返回。 |

降低器还会在优化前裁去不可达块。这个阶段压紧块号，用 `NOP` 保留被删指令的位置，使其他值 ID 继续有效。随后优化器在重建直线函数时才重排指令 ID。[降低器中的 prune](../src/lower.c) · [整数运算与 IR 打印](../src/ir.c) · [优化效果测试](../tests/optimization_tests.c)

## 一个聚合怎样跨越调用边界

以 `make(a, b) -> Ts` 为例，`Ts` 在 Windows x64 上占 16 字节。调用者预留结果空间，把地址放入首个参数寄存器 `RCX`，两个 `i32` 显式参数顺移到 `EDX` 和 `R8D`。被调函数向该地址写入结果，并在 `RAX` 返回这个地址。调用 `sum(value: Ts)` 时，调用者则为按值实参准备独立副本，把副本地址放入 `RCX`。两种地址用途不同，一个用于收回结果，一个承载实参。[struct.ar](../examples/struct.ar) · [x64 后端](../src/backend_x64.c)

| 后端要决定什么 | 当前生成方式 |
| --- | --- |
| 参数放在哪里 | 当前支持的整数及指针参数按位置使用 RCX、RDX、R8、R9，余下参数在栈上传递。1、2、4、8 字节聚合按整数传递，其他正大小聚合间接传递。C 可变参数尾部的窄整数和 bool 在降低时已提升为 i32。 |
| 一个函数需要多少栈 | `frame_layout` 先取各调用所需参数区和副本空间的最大值，供调用点复用。每次调用至少预留 32 字节参数保留区，再为函数自身的对象和临时值安排栈槽。入口已有 8 字节返回地址，调整非空栈帧后，下一次调用前 RSP 按 16 字节对齐。 |
| 如何寻址和复制 | 字段加布局偏移，数组索引按元素大小缩放并保存算好的地址，全局通过 RIP 相对寻址。聚合按固定宽度分块复制，因此传值和返回可能实际搬运多个机器字。 |
| 哪些函数进入汇编 | 有根模块 `main` 时，从它沿优化后的调用边遍历，入队即标记，递归环也只扫描一次。没有该入口时输出全部定义。因此 IR 仍可列出一个已经从最终汇编消失的函数。 |
