# 前端、模块与类型布局

## 一份模块，两种访问方式

`hello.ar` 既写了 `import "basic";`，也写了 `basic :: import "basic";`。前者让 `add` 可直接调用，后者让 `basic::TC` 可被限定访问。`main` 把 `basic::TC` 设为 3 后，`add(1, 2)` 在自己的定义模块调用私有的 `add2`，再读同一份 `TC`，结果为 6。[hello.ar](../examples/hello.ar) · [basic.ar](../examples/basic.ar)

1. **找到文件。** 加载器扫描导入标记，以导入者所在目录为基准补上 `.ar`，取得规范路径。它先登记当前模块，再递归读取依赖。已登记路径可以直接复用，因此菱形导入和循环导入都能结束。
2. **建立可见名称表。** 解析完各文件后，开放导入把导出项的声明 ID 加入导入者的表，命名导入只登记一个模块别名。表按“所属模块、名称字节”排序，相邻同名项触发诊断。
3. **查回原声明。** 用引用处的源码偏移找到所属模块，再二分查名称表。`basic::TC` 先查别名，再查目标模块的导出项。两种导入最终引用同一声明 ID，降低后也就只有一份全局存储。[模块加载与名称解析](../src/modules.c)

## 从字符到语法树

词法器逐个返回带字节区间的 token。解析器按声明和语句递归下降，表达式使用**优先级爬升**。例如读到 `a + b * c` 时，解析 `+` 的右侧只接纳优先级更高的运算，于是先得到 `b * c`。遇到 `a - b - c` 时，第二个减号留给外层循环，得到 `(a - b) - c`。字段和下标先接到左侧节点上，`mat[i, j]` 因而形成两层索引，每层都能单独检查类型和长度。[词法器](../src/lexer.c) · [解析器中的 parse_expression](../src/parser.c)

AST 用数组存放表达式、语句和块，节点之间通过 ID 引用。数组扩容后 ID 仍可用。名称和源码区间则借用合并后的源码缓冲区。解析器按文件边界读取，诊断时再把偏移映射回原文件，从该文件的起点计算行、列。这使导入模块中的错误能指回原文。[AST 数据结构](../src/frontend.h) · [动态数组](../src/array.h) · [诊断定位](../src/diagnostic.c)

## 从类型到字节偏移

以示例中的 `struct Ts { a: i32; b: i32 = 2; c: *i32; }` 为例。Windows x64 上两个整数分别放在偏移 0、4，指针需要 8 字节对齐，恰好从偏移 8 开始。整个对象大小为 16 字节、对齐为 8。`b` 的默认值影响初始化内容，字段偏移只取决于类型和声明顺序。[struct.ar](../examples/struct.ar)

| 类型 | 布局算法 | 后续怎样使用结果 |
| --- | --- | --- |
| struct | 按声明顺序，把当前偏移向上对齐到字段要求，放入字段。末尾补到最大字段对齐。 | 字段访问加固定偏移，结构体数组的相邻元素也满足对齐。 |
| union | 所有成员偏移为 0，取最大成员大小，再补到最大成员对齐。 | 成员共享字节，按值复制覆盖整个对象。 |
| 固定数组 | 按“元素类型、长度”复用数组类型。元素连续排列，大小为长度乘元素大小。 | `index` 用元素大小计算步长，多维数组逐层使用各自的步长。 |
| 整数枚举 | 布局阶段计算底层整数类型和成员位模式。普通枚举自动递增，位枚举自动左移。 | 成员降低为整数常量，可直接作为下标或 `case`。 |

按值嵌套时，布局器先求出字段类型的大小。进入一个类型就标记为“计算中”，完成后缓存布局。如果沿按值依赖再次遇到“计算中”的类型，就发现了循环。指针字段只需目标平台的指针大小，所以结构体可以通过指针引用自身。`sizeof`、`alignof` 和后端寻址都复用这里的布局数据。数组长度和枚举初值在这一阶段走受限的整数表达式求值。[类型与布局实现](../src/types.c) · [实现子集](../NEXT/parser_subset_v0_1.md)
