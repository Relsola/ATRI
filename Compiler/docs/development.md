# 开发约定

面向当前 C23 Stage 0 编译器。协作范围与语言决定以 [AGENTS](../AGENTS.md) 为准；本文件维护通用代码风格、工具经验和验证约定。

## 代码风格

- 类型使用 PascalCase，函数/变量使用 snake_case，枚举/宏常量使用 UPPER_SNAKE_CASE；公共编译器接口沿用 Atri/atri_/ATRI_ 前缀，文件内函数使用 static。
- 结构体以数据为主，操作显式接收指针。保持 C23，不引入 C++ 语法、RAII 包装或其他项目的 internal/defer 宏。
- 沿用所在文件的括号排版与四空格缩进，指针星号靠变量；新增/重写的条件与循环体使用花括号。不因局部排版偏好重排无关代码。
- 非平凡作用域使用表达用途的名称；不要让短变量名迫使读者反复查上下文。复杂条件、多步资源处理和阶段转换分开书写，不压缩成难读的一行。
- 数量/数组下标沿用 size_t/AtriId；目标语言整数的位宽使用对应固定宽度类型。不要把宿主 size_t、目标 i64 和机器指针视为同一语义。
- 优先直接控制流与已有结构，不为一次简单调用抽象通用框架。宏用于确有复用价值的断言、位置捕获等用途，避免实参被重复求值。
- 项目头使用双引号，标准库头使用尖括号。已有穷举 switch 保留编译器对新增枚举的诊断，不为排版统一随意补 default。
- 源码和文档使用 UTF-8，保持自有代码零警告。格式修改限定在本次涉及的区域。

### 注释

优先中文，只解释容易误解的约定、算法原理/不变量、资源所有权、阶段边界及不能直接推断的取舍。不要复述赋值、循环、返回等显而易见的操作，也不为凑数量描述函数名。实现变化时同步修正相关解释。

例如，支配分析应说明“前驱集合取交集”的原因；栈布局应解释返回地址和对齐关系；测试应说明断言检查 IR 常量还是实际执行结果。

### 错误与不变量

文件读取、词法/语法输入、分配和目标限制在对应边界检查并返回诊断。已验证的内部数据按契约使用，不逐层添加重复空值检查、范围夹取或静默返回；必要的不变量用断言/Verifier 表达。

编译器处理的源码本身可能非法，用户诊断不能用仅 Debug 有效的 assert 替代。也不能为了“减少防御代码”删除已有的可失败分配、资源预算或 IR 验证。新增检查要有真实失败路径和明确成本。

### 所有权与阶段

- 明确区分借用源码、AST/IR 自有数组及临时索引；接口说明谁分配、谁释放和借用寿命。C23 使用已有 destroy/cleanup 路径，不照搬 C++ defer/RAII。
- 动态数组扩容会移动内存；跨追加操作保留稳定 ID，避免持有可能失效的元素指针。
- 语义义务与可选优化分开：:= 不能依赖内联开关才合法；“优化前 IR”已完成强制常量求值。
- 更改 IR 指令或类型时，同步降低、常量解释器、Verifier、Dump、优化器、后端和行为测试，避免某阶段静默忽略新操作。

## 工具与临时材料

构建/使用入口见 [README](../README.md#运行整数编译原型)，测试写法和专项入口见[测试说明](../tests/README.md)。继续使用现有 CMake/Ninja/CTest，不复制其他项目的 build.bat 或新增并行测试清单。

- 先看 git status/diff，按当前符号和模块缩小范围；文本检索首选 rg。有实际连接的语义导航工具时按其公开能力使用，不把“安装了扩展”等同于本次会话可调用。
- PowerShell 不会替 rg 展开 Unix 风格通配路径。让 rg 搜索目录并用 -g 过滤：

  ```powershell
  rg -n 'atri_resolve_constants' src tests -g '*.c' -g '*.h'
  rg -n 'CMAKE_C_COMPILER_ID|CMAKE_C_COMPILER_VERSION' build/CMakeFiles -g 'CMakeCCompiler.cmake'
  git diff -- src/lower.c
  git show HEAD:Compiler/src/lower.c
  git diff --check
  ```

  Git 仓库在父目录 ATRI，git show 的路径相对仓库根；不要把基线输出覆盖到当前工作区。

- 有空格的可执行路径使用调用运算符和独立参数。JSON 编码不是 shell 转义；多行正文写文件或单引号 here-string，不把未经转义的文本拼进嵌套 shell。
- 原生命令返回后立即检查退出码，成功后才执行依赖步骤；构建与测试不能并行写同一输出目录。不要通过截断输出的管道隐藏首个失败。
- 文件/进程操作使用单一 shell；Windows 删除/移动用 LiteralPath 并先确认目标位于本次目录，不把 PowerShell 枚举结果拼成 cmd 删除命令。
- 一次性脚本、验证日志和导出使用 build/agent/<任务>/；正式测试夹具仍在 tests/cases，生成绑定和可执行文件由现有构建规则管理。派生产物修改生成器，不手改输出文件。
- 工具从 PATH 或明确的 CMake 配置定位，不把本机绝对安装路径写入项目脚本。以当前 CMake 缓存、命令和产物确认实际工具，不照搬参考项目版本或服务地址。
- 辅助脚本优先现有 runner 与标准库；确需 Python 包时使用 uv 临时环境，记录用途/版本，不修改全局环境或把临时工具变成产品依赖。

## 验证与调试

先构建当前配置，再运行对应的 CTest 分组。CMake 的 Debug/Release 控制宿主编译器的构建，ATRI 的 `-O0`、`-O1` 和 `-O2` 控制输入程序使用的后端。

| 改动 | 优先验证 |
| --- | --- |
| 纯文档 | 对照相关源码、链接、git diff --check |
| 仅注释 | 核对有效代码未变；注释边界/编码或构建输入变化时补构建 |
| 词法/解析/诊断 | frontend、compiler、control-flow 中相关用例 |
| 类型/常量求值 | compiler、control-flow；涉及生成行为时补原生执行 |
| IR/优化 | `optimization` 检查独立的字节码优化，`ir-verifier` 检查 IR 约束，`compiler-pipeline` 检查 O1 的 LLVM IR 变换及 O0/O1/O2 产物 |
| x64/调用约定/访存 | Windows 原生执行，核对参数、返回、别名及必要汇编预期 |
| CMake/测试驱动/共享测试辅助 | 构建并运行受影响测试；共享路径改动检查全部分组 |

共享阶段改动按实际影响扩大验证，不为每个小改动重复全量运行。测试断言不能随 NDEBUG 消失。性能测量按任务需要单独执行，注明构建、输入、单位和测量区间；测试通过或汇编变短不等于已证明性能提升。

失败保留完整输出、退出码与复现输入，先定位首次失败。运行时错误在断点工具确实可用时优先单步/变量检查；工具缺失时明确能力边界，使用现有 CLI、IR/汇编和最小复现，不猜测其他项目的调试 API。

前台测试等待退出并检查状态；另行启动后台辅助进程时记录 PID 和日志，结束后只清理本次进程及其子进程，不终止用户已有实例。不要把构建成功、解析成功、IR 结构正确、真实机器执行、优化效果和性能测量混称为“验证通过”。
